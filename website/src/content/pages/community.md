## The participation ladder

You do not need permission, and you do not need to start deep. Each rung is a
real contribution:

1. **Discover** — read the [mental model](https://github.com/knograph/kno/blob/main/docs/mental-model.md). One page, and the rest makes sense.
2. **Try** — run the [quickstart](#quickstart). It costs nothing.
3. **Star** — stars are signal, not currency. The repo is [knograph/kno](https://github.com/knograph/kno).
4. **Use** — point Kno at a real provider behind a budget cap. Something breaks? That is a bug report waiting to happen.
5. **Discuss** — usage questions and open-ended discussion live in [GitHub Discussions](https://github.com/knograph/kno/discussions).
6. **Report** — issues follow templates, with labels `bug`, `enhancement`, or `adapter`. Security reports have a [separate path](https://github.com/knograph/kno/blob/main/SECURITY.md).
7. **Improve docs** — the cookbook is task-shaped on purpose. A recipe for your stack is a contribution.
8. **Build an adapter or judge** — Ring-1 adapters and judge prompts are the natural on-ramps. See [where to start](https://github.com/knograph/kno/blob/main/CONTRIBUTING.md#where-to-start).
9. **Core contribution** — the loop is open: plan first, adversarial review, then code.
10. **Repeat** — the debt ledger is public, every entry has a repayment trigger, and repayment is ordinary work.

## How we work

Before you write code, read [CONTRIBUTING.md](https://github.com/knograph/kno/blob/main/CONTRIBUTING.md) —
the short version: the vocabulary is law, plan first, review adversarially,
then code. Good-first-issue is a curated pipeline, not a label of neglect:
each one has context, a plan, and a clear completion condition.
