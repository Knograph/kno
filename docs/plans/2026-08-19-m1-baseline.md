# Plan: Baseline — the first pipeline stage (Milestone 1)

- **Date:** 2026-08-19
- **Status:** Phase 1 complete — amended after two adversarial passes, both BLOCK
- **Author:** DeVaris Brown
- **Depends on:** M0 complete (#1, #2, #7–#11, #14 merged)

## Problem statement

`main` has the contract, the gates, the Ring-0 interfaces, the error grammar, and the budget guard.
Nothing runs. There is no stage, no adapter, no store, no CLI verb.

M1 delivers **Baseline**: run an agent over a set of eval Cases, score each Response against a
Goal, split dev/holdout at ingestion, persist every trace, and survive interruption. It is the
first stage of the five, and everything downstream reads what it writes.

Three properties make this milestone different from M0. Each is a place where being wrong is
expensive and quiet:

1. **It is the first code that spends money.** Until now the budget guard has had no callers.
2. **It is the first code that fans out.** Concurrent workers over one iterator is where the
   borrow-for-one-iteration contract (debt 8) stops being documentation.
3. **It establishes the holdout seal.** Every statistical claim the tool later makes depends on
   nothing reading `SPLIT_HOLDOUT` before Validate. This is the milestone that makes that true, or
   fails to.

### Scope: a vertical slice, deliberately without a real provider

M1 runs end to end against a **deterministic fake agent** and an **exact-match Goal**. No OpenAI,
no Anthropic, no judge, no BAML.

That is not timidity, it is sequencing. The hard parts of Baseline are the split, the seal, the
checkpointing, the concurrency, and the event stream — all of which are *harder* to test against a
non-deterministic provider, and none of which need one. Wiring a real provider into an unproven
executor would mean debugging two things at once, with a bill.

The first real adapter lands in M2, against machinery already known to work.

### Non-goals

- Value, Select, Validate, Export stages.
- Any hosted provider adapter, and therefore any actual spend. `Tuner` stays unimplemented.
- BAML judges and `judge calibrate`.
- The TUI dashboard. Baseline emits events; rendering them is M2.
- `kno init`, `kno mine`, `kno run` — the CLI gets `kno baseline` only.
- The connect-rpc API.

## Milestone structure — five PRs

M0 taught that a branch mixing independent workstreams gets a worse review than several small ones.
Split along the same seam CLAUDE.md's parallelization table uses, with proto first:

## Proposed design

### 0. Budget state must survive process death (M1-0)

**This is a P0 spend-safety gap in already-merged code, not accepted debt.** Both reviewers found
it, and it is verified: `stats/budget.Guard` has no persistence of any kind. `New()` always starts
at `spent: 0`. So `kno baseline --resume` constructs a fresh Guard with total amnesia about money
the killed run already spent — a run near its `max_cost_usd` can authorize nearly the whole cap a
second time, for up to 2x the intended spend across one kill/resume cycle.

It shipped unnoticed in #14 precisely because nothing called the guard yet. M1 is where it would
bite, so it is fixed first, before anything spends:

```go
// Restore reseeds settled spend. Callers reconstruct it from the store rather
// than trusting an in-memory total no process survives.
func (g *Guard) Restore(spent Spend)
```

Resume sums `cost_usd_micros` and call counts over the persisted `responses` rows for the run and
calls `Restore` before authorizing anything. The store is the source of truth for money spent,
because it is the only thing that outlives the process.

**Accepted, irreducible:** a SIGKILL between a provider accepting a request and the local process
persisting anything is a dark spend that no architecture here can observe — bounded by
`concurrency` in-flight calls' worth of estimated cost. Named as a risk rather than left silent.

### 1. `Run` and the event spine (M1-1)

Deferred from M0 deliberately (Phase-1 finding A5): freezing an event schema before anything emits
an event invites immediate `reserved`-range surgery. Baseline is the first producer, so the schema
is now designed against a real one.

```protobuf
message Run {
  string id = 1;              // ULID
  Stage stage = 2;            // which stage produced it
  string created_at = 3;      // RFC 3339
  AgentRef agent = 4;
  string goal_name = 5;
  Direction goal_direction = 6;
  Budget budget = 7;
  RunStatus status = 8;
  string incomplete_reason = 9;
}

enum Stage   { STAGE_UNSPECIFIED = 0; STAGE_BASELINE = 1; STAGE_VALUE = 2;
               STAGE_SELECT = 3; STAGE_VALIDATE = 4; STAGE_EXPORT = 5; }
enum RunStatus { RUN_STATUS_UNSPECIFIED = 0; RUN_STATUS_RUNNING = 1;
                 RUN_STATUS_COMPLETED = 2; RUN_STATUS_FAILED = 3;
                 RUN_STATUS_BUDGET_STOPPED = 4; RUN_STATUS_INTERRUPTED = 5; }

message Event {
  string run_id = 1;
  string emitted_at = 2;
  int64 sequence = 3;         // monotonic per run; gaps mean lost events
  oneof payload {
    RunStarted run_started = 10;
    CaseScored case_scored = 11;
    CaseErrored case_errored = 15;   // distinct: an error is not a score
    StageProgress stage_progress = 12;
    SpendRecorded spend_recorded = 13;
    RunFinished run_finished = 14;
  }
}
```

`sequence` exists so a consumer can detect loss rather than silently under-report. Debt 2 (no typed
`Run`) is retired by this PR.

`CaseErrored` is separate from `CaseScored` deliberately, resolving what was open question 3. It is
the observable form of the denominator rule in §3a: an errored Case is not a scored Case, and the
event stream must carry the same three counts the `Report` does, or the live view and the persisted
result disagree about the sample.

**Events carry IDs and metrics, never content — and the TUI works within that.** The M2 dashboard
shows the Case currently under evaluation by `id` and `tags`, and Assets by `title`. Those fields
exist for exactly this. Stated now so the TUI workstream does not discover late that it needs to
bypass the event stream and query `store` directly for a live view.

**Events carry IDs and metrics, never content.** No `Case.input`, no `Response.output`. CLAUDE.md
forbids conversation content in telemetry and in logs above DEBUG, and the event stream feeds
logs, the TUI, and eventually SSE. Making content unrepresentable is stronger than remembering not
to include it.

### 2. `store` (M1-2)

SQLite. Tables: `runs`, `cases`, `responses`, `scores`, `events`, `run_checkpoints`.

**Driver: `modernc.org/sqlite` (pure Go).** The plan named no driver, which Phase-1 review
correctly called a Phase-0-decidable architectural choice. `mattn/go-sqlite3` is faster on
write-heavy paths but requires cgo, which breaks `CGO_ENABLED=0` and the
darwin/linux/windows x amd64/arm64 matrix DESIGN.md promises as a single static binary. The binary
promise wins; the throughput cost is analyzed below and is not binding in production.

**Commit granularity: one transaction per scored Case.** Reviewer flagged the write amplification —
1M cases could mean 1M commits, capping the single writer near ~500/sec. That ceiling is real and
deliberately accepted, because it does not bind where it matters: a real agent call takes on the
order of a second, so a 2ms commit is noise. It binds only against the fake agent, which is a
benchmark artifact rather than a workload. Batching would trade that for re-spending a whole batch
after a crash, which is the wrong trade when the thing being re-spent is money.

**The score row IS the done marker.** The original sketch had a separate `checkpoints` table, which
Phase-1 review showed creates a two-transaction hazard: a SIGKILL between the score commit and the
checkpoint commit leaves a Case fully scored (money spent) that resume would re-run — reopening the
double-spend the design exists to prevent. Resume asks `scores` directly, so the answer to "is this
Case done" and the record of it being done are the same row, written once. `run_checkpoints` holds
run-level metadata only (fingerprint, budget totals), never per-Case progress.

**Concurrency is internal.** A single writer goroutine consumes a bounded results channel; WAL
mode. Both are implementation details of the SQLite backend and must not appear in the `store`
interface — otherwise a future Postgres backend inherits an artificial single-writer bottleneck it
does not need, and "swappable" becomes true in name only.

**Resume's done-set.** Completed Case IDs load into an in-memory set: ~26 bytes per ULID, so ~26 MB
at 1M Cases. Bounded and acceptable, but it is a real exception to the streaming promise made
elsewhere in this plan, so it is stated rather than glossed. The alternative — a point query per
Case — puts 1M round trips through the writer that the previous paragraph just established as the
bottleneck.

**The fingerprint, pinned.** `ErrCheckpointStale` triggers on any change to: the content hash of
the eval source, the goal name and direction, the agent ref, `split_seed`, and `holdout_frac`.
Content, not path and mtime — an in-place edit of the JSONL must invalidate the resume, and a
`git checkout` that rewrites mtime without changing content must not. A test mutates each input
independently and asserts staleness is caught.

### 3. `adapters/evals/jsonl` and the holdout seal (M1-3)

The first Ring-1 adapter. Reads JSONL, yields `*Case`, and **passes `coretest.ConformIterator`** —
the harness written in M0c-3 gets its first real subject. Per debt 18, this package installs
`goleak.VerifyTestMain`.

**The split happens at ingestion and is deterministic.** `hash(case.id + run_salt) < holdout_frac`
rather than a shuffle, so the same Case lands in the same split on every run of the same eval set.
A non-deterministic split would make two runs incomparable while looking comparable.

**The seal is engine-side, and it is a distinct TYPE.** Phase-1 review killed the original
sketch, correctly. It proposed `Seal(core.Evals) core.Evals` — returning the same interface it
consumed, so nothing distinguished a sealed source from a raw one. Any code that held the raw
adapter and simply forgot to call `Seal` would compile cleanly and read holdout. The canary test
would then prove only that *today's* `core.Baseline` doesn't leak; it is a regression test on one
call site, not an enforcement mechanism.

```go
// SealedEvals yields only SPLIT_DEV cases. It is a distinct type, not an alias,
// so a function that requires one cannot be handed a raw Evals.
type SealedEvals struct{ /* unexported */ }

func Seal(e core.Evals) *SealedEvals

// Baseline REQUIRES a SealedEvals. Passing an unsealed source is a compile
// error, not a discipline lapse discovered in review three months from now.
func Baseline(ctx context.Context, ev *SealedEvals, ...) error
```

**`Unseal` is cut from M1 entirely.** The original sketch took a `validate.Token` — from a package
that does not exist and is not due until M4. Shipping that signature now means either a stub
`Token` any caller can construct (unsealing the holdout three milestones before the stage meant to
be its sole issuer exists), or a code sketch that does not compile. This is the same speculative
design the M0c plan rejected for `budget.Estimate()`, and it gets the same treatment: `Unseal`,
what a `Token` is, and who can mint one are designed at Validate, with the context to do it right.
M1 has no legitimate use for it — Baseline only ever seals.

**The canary test** remains, downgraded to what it actually is: a regression test that Baseline's
current path does not leak. The type is the enforcement; the canary catches the case where someone
adds an unsafe accessor later.

**The split is keyed on Case ID and nothing else.** The original sketch said
`hash(case.id + run_salt)` without ever defining `run_salt` — and the name invites exactly the
wrong answer. A per-run salt would let a Case migrate dev → holdout between runs, which does not
prevent the leak prime directive 5 exists to stop, it merely delays it by one run: a Case scored
and reported in dev on Monday becomes "untouched holdout" on Tuesday.

The split is `stableHash(case.id) mod 10000 < holdout_frac * 10000`. No salt by default. Adding
Cases to an eval set therefore never moves the ones already there. An optional `split_seed` may be
set in `kno.yaml` for a deliberate re-split; it is recorded on the `Run` and is part of the resume
fingerprint, so changing it invalidates a resume rather than silently reclassifying mid-run.

**Small eval sets get an explicit answer, not an open question.** With `holdout_frac = 0.2`, a
12-Case set yields a 2-Case holdout, and hash luck can yield zero. Decided:

- **Zero holdout Cases → refuse at ingestion.** A run that cannot ever produce a holdout number is
  not a run; it fails with an `Actionable` naming the minimum.
- **Fewer than `min_holdout` (default 20) → proceed, but mark it.** The `Run` carries
  `holdout_underpowered`, the CLI says so plainly, and the number is reported with that caveat
  attached rather than quietly presented as if it meant the same thing.

### 3a. The denominator, pinned

Phase-1 review found that Baseline's own score had no defined denominator, and that every future
delta is computed against it. Left unpinned, a provider outage in one run and not another compares
scores over different implicit populations — silently. Decided:

- **Errored Cases are excluded from the score, not counted as failures.** An agent that returned a
  500 did not answer badly; it did not answer. Scoring infrastructure failure as task failure
  biases the baseline downward and makes any later Asset look better than it is.
- **`Report` carries all three counts** — attempted, scored, errored — so exclusion is visible
  rather than implied.
- **Any later delta is computed over the intersection** of Cases scored in both runs. This is the
  invariant that makes exclusion safe, and it gets a test now, in M1, even though the first
  consumer is M2.
- **A run whose error rate exceeds `max_error_rate` (default 5%) is not a baseline.** It completes,
  records everything, and is marked `RUN_STATUS_COMPLETED` with `incomplete_reason` set, so
  downstream stages refuse to treat it as a clean reference.

### 4. `executor` (M1-4)

A bounded worker pool over `iter.Seq2`, with checkpointing. Phase-1 review found this section
described the goal without a protocol — and since M1-4 is a standalone parallel PR, whoever
implemented it would have invented one. Written out:

```
  producer goroutine            workers (N)              writer goroutine
  ─────────────────────         ───────────              ────────────────
  range sealed.Cases(ctx)  ──▶  recv case          ──▶   recv result
    clone each *Case             Authorize(est)          one txn per Case
    select { send / ctx }        defer Release()         emits events
                                 Invoke, Score
                                 Settle(actual)
```

Rules that make it correct, each answering a specific finding:

- **The clone happens in the producer, before the send.** Cloning after the pointer crosses the
  channel leaves a window where the producer's next iteration can reuse the backing memory —
  exactly debt 8's race. `proto.Clone` per Case is the cost of honoring the borrow contract; it is
  paid once per Case against an agent call that is orders of magnitude more expensive.
- **Every send is `select` on the shutdown context.** Without it, a producer can block forever
  handing off to workers that are all stuck, with no goroutine left alive to service Ctrl-C.
- **The executor owns an internal cancelable context** derived from the caller's. Shutdown is
  triggered top-down (Ctrl-C) *or* bottom-up (budget exhausted, a fatal iterator error, a worker
  panic), and bottom-up needs a way to stop the producer's range loop. That is what the internal
  context is for.
- **A fatal iterator error stops the range and drains.** Ring-0 says a yielded error is fatal, but
  up to N Cases are already in flight. They are allowed to finish and be persisted — their money is
  already spent — then the run ends `RUN_STATUS_FAILED`. Aborting them would discard paid-for work.
- **Every path reaches `defer res.Release()`.** Worker panics are recovered at the worker boundary
  so the deferred release runs, the Case is recorded as errored, and the pool keeps its shape.
- **Retries re-Authorize.** A retry is a new provider call, so it takes a new reservation; the
  failed attempt settles with its actual cost, which may be zero if the provider rejected it. Retry
  is bounded and backs off on `errs.ErrRateLimited`.
- `goleak.VerifyTestMain` in this package as well as the adapter — this is where goroutines
  actually proliferate.

**Signal handling has a deadline.** First Ctrl-C drains and checkpoints. Second Ctrl-C exits
immediately with `ExitError`. A drain that exceeds `shutdown_timeout` (default 30s) force-exits the
same way, because a worker blocked on a provider with no timeout must not hang the process
indefinitely — the state that reopens the dark-spend window in §0.

### 5. `core.Baseline`, the fake agent, and `kno baseline` (M1-5)

The stage itself: iterate sealed dev Cases, invoke the Agent through the executor, score each
Response, persist, emit events, respect the budget.

- **Every Agent call goes through `budget.Guard.Authorize`.** This is the first caller, and the
  path that finally makes debt 11 real. The CLI parses `max_cost_usd` into `Limits`, so the
  `make test-live` grep interlock can be replaced with an actual assertion.
- `adapters/agent/fake`: deterministic, zero cost, and a **first-class adapter rather than a test
  double**, because the CLI must be exercisable without a provider. Its configuration surface is
  what decides whether the executor is actually proven, so Phase-1 review's list is the spec:
  - **latency implemented as a real `ctx` select**, not `time.Sleep` — otherwise cancellation
    *during* a call is never exercised, only cancellation before one.
  - **scheduled failures**, so errored-Case handling and the denominator rule are exercised.
  - **scheduled `errs.ErrRateLimited`**, so the executor's backoff is built and tested in M1. The
    sentinel already exists; without a fake that can produce it, backoff would first be exercised
    by a paid adapter in M2. That is the wrong place to find out it is wrong.
  - It still will not catch partial reads, connection reuse, or mid-stream deadlines. Those are
    M2's, and this plan claims only what the fake actually demonstrates.
- `goal/exactmatch`: `Score = 1` on exact match, `0` otherwise, `DIRECTION_MAXIMIZE`.
- `kno baseline --evals ./cases.jsonl --agent fake: --goal exact-match` prints a summary, ends by
  naming the next command, and exits `0`/`1`/`2` per the error grammar.

## Alternatives considered

**A. Start with a real openai-compatible adapter instead of a fake.**
Rejected. It couples the first executor, the first store, and the first stage to a
non-deterministic, paid dependency. Every failure would have two candidate causes, and the test
suite could not run in CI. The fake is also permanently useful: it is how `kno` stays demoable and
how CI exercises the CLI.

**B. One PR for the whole slice.**
Rejected. It is the M0a mistake — proto, storage, concurrency, and CLI reviewed as one diff, where
the irreversible part (the event schema) competes for attention with the mechanical parts.

**C. Put the holdout seal in the `Evals` adapter.**
Rejected in M0c and still rejected: adapters are the layer with the least context and the most
implementations, and a seal there is advisory at best.

**D. Skip checkpointing in M1; add it when runs get expensive.**
Rejected. Checkpointing is not a performance feature, it is the reason an interrupted run does not
re-spend. Adding it after the executor exists means retrofitting idempotency into a store schema
already in use.

## Edge cases and mitigations

| # | Edge case | Mitigation |
|---|---|---|
| 1 | A holdout Case reaches Baseline | Engine-side seal + the panicking canary Case (§3) |
| 2 | Non-deterministic split makes runs incomparable | Deterministic hash split, tested for stability across runs |
| 3 | Two workers mutate the same yielded `*Case` | Per-worker clone; 128-worker `-race` test over a buffer-reusing producer (debt 8) |
| 4 | Resume double-spends | Idempotent writes keyed by (run_id, case_id); kill/resume test asserts `Spent()` unchanged for completed cases |
| 5 | Resume against changed inputs | `ErrCheckpointStale` when the evals/goal/agent fingerprint differs |
| 6 | An agent error kills the run | Errored Responses are recorded, not dropped; the run continues and the report says how many failed |
| 7 | Conversation content leaks into events or logs | Content is unrepresentable in `Event`; a test asserts no event field carries `input`/`output` |
| 8 | Ctrl-C loses the in-flight case | Checkpoint after each scored Case; signal handler drains and checkpoints before exit |
| 9 | Budget exhausted mid-run | Run stops with `RUN_STATUS_BUDGET_STOPPED` and exit 2, resumable — not a failure |
| 10 | SQLite locking under concurrent workers | Single writer goroutine; workers send results over a channel. WAL mode |
| 11 | Event sequence gaps go unnoticed | Monotonic `sequence` per run; the consumer test asserts detection |
| 12 | A 1M-case eval set is loaded into RAM | Streaming end to end; a test runs a large synthetic set under a memory ceiling |

## Test plan

**Unit** — split determinism and distribution; `store` idempotency; `executor` bounded concurrency
and cancellation; exact-match Goal; `Actionable` exit codes through the CLI.

**Invariant**
- **The holdout canary** (§3) — the single most important test in this milestone.
- No event message can carry conversation content (descriptor-level, like the M0b enum test).
- Debt 8's shared-pointer race test.

**Integration (fixtures, no network)**
- Kill mid-run, resume, assert identical results and no double-spend.
- Resume with changed inputs fails with `ErrCheckpointStale`.
- A full `kno baseline` run against the fake agent, golden-tested on stdout and exit code.
- Budget restoration: run, kill, resume, and assert the guard's `Spent()` after `Restore` equals
  the persisted total — the test that would have caught §0.

**Lazy-iteration test instead of a memory ceiling.** The original plan promised "a large synthetic
set under a memory ceiling". Phase-1 review is right that this is GC-timing dependent and would be
quarantined under the repo's own flaky policy within a week. Replaced with a deterministic test of
the actual property: a counting producer over 1M synthetic Cases, a consumer that stops at N, and
an assertion that exactly N+buffer Cases were ever read. That proves laziness — which is what the
streaming promise means — without measuring the heap.

**Deferred**: judge calibration and provider fixtures land with the first real adapter (M2).

## Rollback story

Additive. Revert the squash commits. The lasting artifacts are the proto additions (baseline for
`buf breaking`) and the SQLite schema — which has no users yet, so a schema change in M2 needs no
migration. Stated now so that stops being true deliberately rather than by surprise.

## Open questions

All three are now resolved in the design above, per Phase-1 review's point that unresolved
questions mean a plan is not ready for sign-off:

1. **Split**: keyed on Case ID alone, no per-run salt. `holdout_frac` default 0.2 (§3).
2. **Small eval sets**: refuse at zero holdout Cases; proceed but mark `holdout_underpowered`
   below `min_holdout` (default 20) (§3).
3. **Errored Cases**: a distinct `CaseErrored` event, excluded from the score, counted separately
   (§1, §3a).
