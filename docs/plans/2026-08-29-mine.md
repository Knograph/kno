# mine: turn production transcripts into an eval set

DESIGN:294 places `mine` in v0.1 deliberately: "the number-one adoption killer for eval
tooling is 'I don't have an eval set,' and production transcripts where a human corrected the
agent are weak labels sitting in everyone's logs."

**Phase-1 re-reviewed 2026-08-29 — verdict: not ready as written.** Three load-bearing
claims were false under the first draft's own scope: the weak-label marker died at ingestion
(so the honesty claim was a claim, not a property), the identity rule reintroduced the exact
split-instability failure the jsonl adapter's own comments reject, and the pairing rule
manufactured adversarial expecteds from the modal human reply. All eleven findings are
folded in and tagged below; the central ones are redesigned rather than accepted.

## Problem

Most teams have transcripts, not Cases: chat logs, ticket threads, support conversations
where a human corrected the agent. `mine` converts those into `cases.jsonl` with honest
provenance — a WEAK-LABEL import, not a synthetic-data generator. The honesty must survive
ingestion, not die at the Run boundary.

## Design

### `kno mine`

```
kno mine --logs <transcript-file|dir> --format auto|jsonl-chat|markdown|csv
         --agent-name <name> --mode immediate|resolution --out cases.jsonl
```

`--logs` because DESIGN:294 is the source of truth and says `kno mine --logs ./convos/` —
the first draft's `--source` was a silent drift. *(finding 9)*

### The weak-label marker that actually survives (finding 1, redesigned)

`common.proto`'s `Provenance.derived` ALREADY exists, with a comment that literally
describes mine ("Set when the record was derived rather than authored — e.g. mined from a
transcript where a human corrected the agent"). The first draft's tags suggestion was the
wrong home: tags are consumed for failure-cluster routing, and a `weak_label:true` tag
injects a routing term into the clustering space.

The path, all three legs in this plan:

1. **The jsonl on-disk format gains additive provenance fields** (`derived`,
   `derivation_note`, `source_ref`) — a contract change with golden-file impact, counted
   as the schema work it is. The jsonl adapter round-trips them into `Case.Provenance`
   instead of clobbering everything to `"jsonl"`.
2. **The Run record carries a weak-label count** — an additive field
   (`weak_label_case_count`) written at run-close, so the report can say "weak-label
   eval" and the number travels like the other case counts.
3. **The report line exists**: the CLI prints the count when nonzero, and `--json`
   carries it. The end-to-end test drives a mined set through `fake:` and asserts the
   count on the Run — the test the first draft would have failed.

The proto section below reflects this; "Proto/schema impact: None" was the first draft's
core error.

### The identity rule (finding 2, redesigned — content-keyed, never positional)

`id = ULID-shaped(content-hash)`, where content-hash = hash(thread identity, question
text, expected text, **parser version**). The parser version is IN the hash so a parser
bugfix re-mining everything is loud, not silent. Turn indices are banned: the jsonl
adapter's own comment documents why positional ids are fatal ("inserting a line silently
reclassified every Case after it... a Case scored and reported as dev on Monday becomes
untouched holdout on Tuesday"), and the first draft's `(file, thread, turn)` id was
exactly that failure. Content-keyed ids keep the split's guarantee — adding turns never
moves the ones already there. The ULID-shaped encoding (timestamp prefix from mine-time,
randomness from the content hash) honors `case.proto`'s ULID contract drift the review
noted; constructed from the hash, no new dependency.

### The pairing rule (finding 3, redesigned — filters before labels)

A human reply is a label only when it contains an ANSWER. The modal reply classes —
"Thanks, that worked!", "I'll escalate this", "Yes, exactly that" (quoting the question
back), "No wait, I misread" — are filtered before becoming Cases, each with its own
count. Two modes:

- `--mode immediate`: the human reply to an agent answer, AFTER the filters, with
  chit-chat stripped and the correction clause extracted ("No, it should be X, and also
  can you check invoice #42" → expected = "it should be X").
- `--mode resolution` (default): the THREAD's final resolution as `expected` — the
  convention the vendor recipes already sell ("the answer that closed it"), strictly
  stronger than the immediate reply.

And the goal-mode declaration the first draft never made: mined Cases carry no rubric, so
the plan declares which Goals they are honest under — **judge goals** and **exact-match
only when `--mode resolution` shaped the expected to a short answer**. The cookbook says
it; the defaults do not silently produce depressed exact-match numbers.

### Agent identity and format schemas (finding 5, pinned)

- JSONL-chat: role fields (`role: "assistant"|"user"|"human"|"agent"` — the schema pins
  the vocabulary), message ids required for thread identity.
- Markdown: `--agent-name` is REQUIRED (refused otherwise) — export tools label the bot
  "AI:", "bot:", or a person's name, and a wrong guess pairs the whole file wrong. The
  run prints a speaker inventory and a per-file pairing-rate summary, so a 0-pair or
  all-pair run is visible, not silent.
- CSV: `question`/`answer` columns; missing columns are fatal, named.

### The token cap (finding 6, honest and consistent)

The repo's own counter — `pricing.countTokens`, the bytes-divisor tokenizer used for
reservations — is the cap's counting mechanism: deterministic, already present, no new
dependency, and consistent with every other number Kno computes. It is labeled exactly as
what it is (an approximation, the same one reservations use). The cap value is IN the id
hash (a cap change re-ids loudly), and a question that alone exceeds the cap is dropped
with a count, never truncated mid-question.

### `--review` (finding 4, redesigned — review state is durable)

- `--review` without a TTY is REFUSED (non-zero exit, fix line naming `--yes`-style
  keep-all) — the first draft's silent keep-all was the mirror-image of the silent-drop
  the adapter contract exists to prevent, inflating the denominator with unvetted
  garbage.
- Review decisions (keep/edit/drop) are written to a review MANIFEST next to the output;
  re-mining reads the manifest and preserves drops — a curated drop can never resurrect.
- The manifest is the "this set was reviewed" marker; the pipeline can tell reviewed from
  not.

### Cross-source duplicates and the split (finding 7)

Exact-duplicate turns across `--logs` files are deduplicated by content hash with a
reported count — deterministic, no embedding pipeline. The residual caveat is documented
in the cookbook: near-duplicate (non-exact) questions can straddle the split, and Select
cannot see the holdout, so the twin-across-split case is named rather than pretended away.

### PII (finding 10)

Mined Cases are the most PII-dense input the tool touches. The cookbook entry says it
plainly: transcripts are end-user data, `cases.jsonl` is yours to protect, `kno purge`
covers the store but not your file, and export-to-fine-tuning inherits whatever the
transcripts carried. `SECURITY.md`'s retention section gets the cross-reference.

## Alternatives considered

**Ask the user to curate from day one.** Rejected: the adoption killer DESIGN names; the
recipes' curation pass becomes the documented SECOND step.

**An LLM-powered mine.** Rejected: a spend path where a model writes the eval standard is
a conflict of interest. Weak labels from HUMANS are the honest floor.

**The first draft's positional ids / tags marker / immediate-reply-only pairing.** All
three rejected in review, recorded so the next reader sees why.

`cli/` (`kno mine`), `adapters/evals/mine/` (deterministic parsers), `adapters/evals/jsonl`

## Proto / schema impact

Additive: jsonl record format gains optional provenance fields; `Run` gains
`weak_label_case_count`. No cardinality changes; `buf breaking` passes.

## Edge cases

| Case | Behavior |
|---|---|
| A transcript with no human replies | Zero Cases, exit 0 with "mined 0 Cases; this source has no weak labels" — a finding, not an error; `--min-cases N` exists for CI gating |
| Format sniff ambiguous | Fails loud, names the candidates, `--format` forces |
| A turn pair already mined | Idempotent by content-hash id — same id, same Case |
| Gratitude/escalation/quote-back replies | Filtered with per-class counts |
| Markdown without `--agent-name` | Refused, fix line names the flag |
| A question alone exceeding the cap | Dropped with a count, never truncated mid-question |
| Non-TTY during `--review` | Refused (exit, fix line) — not silent keep-all |
| A parser bugfix changes extraction | New parser version in the id hash — re-mine is loud |
| Huge source | Streaming read, same memory profile as the jsonl adapter |

## Test plan

- Golden files per format × mode, including every filter class and the counter-question
  drop.
- The marker end-to-end: mined set → `fake:` baseline → Run carries the weak-label count →
  report line prints.
- Idempotence: mine twice, byte-identical; a curated drop survives re-mine via the
  manifest.
- Identity: content-keyed ids are stable under insertion (the jsonl split-stability test,
  re-run for mine); parser-version change re-ids loudly.
- Cap: the id includes the cap; question-over-cap drops with a count.
- Split: mined sets divide identically to a hand-written set with the same ids.
- `--review` non-TTY refusal; markdown `--agent-name` refusal; `--min-cases` gating.

## Rollback

Delete the command and the extraction package; the additive jsonl/proto fields are
unreferenced by pre-existing code.

## Docs impact

Cookbook entry ("Mine an eval set from your transcripts"), the vendor recipes' curation
sections re-targeted (fit vs quality), mental model (the weak-label honesty note),
retention/SECURITY cross-ref, CLI help snapshot, CHANGELOG.

## Accepted risks

- **Weak labels are weak — and the marker now proves it.** Bias-shaped, not just
  noise-shaped; the filters close the modal classes, the `derived` stamp and the Run
  count make the rest visible.
- **Transcript formats are endless.** Three pinned schemas ship; `--format` errors name
  what is missing.
- **Markdown pairing is best-effort even with `--agent-name`.** The pairing-rate summary
  is the honesty instrument; formats with role fields are the recommended path.
