# `kno demo`: the whole loop in one command, against `fake:`, for free

The onboarding stage nobody owns. `baseline`, `value`, `select`, `export` and `report` all
ship; what does not ship is the ten minutes before the first one of them runs.

Written against the code, not against the idea of it: the scenario below is the one
`tapes/quickstart.tape` already records, the flags below are the flags those five commands
actually declare, and the honest-numbers problem is the one the tape's own comments already
solved once. Where this plan proposes something the tree does not have (there is no
`go:embed` anywhere in the repo today), it says so and defends it.

**Phase-1 re-reviewed 2026-08-30 — verdict: amend; amendments applied.** Four things changed.
The two ***(verify)*** tags are resolved as settled fact and the hedges deleted: the consent
chain is correct as written (`fake.Agent` implements no `WorstCase()`, so it is not a
`core.Estimator`, so the scalar path yields zero), and `go:embed` needs no build-system change
(neither `.goreleaser.yaml` nor the `Makefile` mentions embed patterns, archive inclusion
lists, or `trimpath`/`ldflags` interactions with embedding). The dominant finding is an error
in this plan's own reasoning: the claim that a missing flag would be "visible as a
compile-time struct field" was **false** — a literal struct takes Go's zero value, not the
flag's registered cobra default — and it is replaced by the real hazard plus a
defaults-parity mechanism *(F1)*. `--force` is narrowed from "clear the directory" to
"delete demo-owned filenames", and the demo now writes its own `.gitignore` *(F2)*. The
unmeasured 30-second gate is downgraded to measure-then-pin *(F3)*. Confirmed sound and not
reworked: the cwd-vs-temp-dir reasoning, the structural config-isolation claim, the honesty
epilogue and its golden, and the exit-code claims.

## Problem

Time-to-first-value is roughly ten minutes and every minute of it is manual. The README's
quickstart (`README.md:108`) asks a new user to hand-author a JSONL eval file, run
`kno baseline`, copy a generated run ID out of the output, hand-author a second JSONL pool
file, and run `kno value` with the copied ID — before a single number appears. Four of those
five steps are typing, and the one that produces the payoff is last.

Three specific costs:

- **The run-ID copy step is the drop-off.** `newRunID` (`cli/render.go:38`) is
  `20060102T150405` plus six random bytes. Between `kno baseline` and `kno value` the user
  must find, select, and paste a 27-character string. The tape avoids this by passing
  `--run-id qs`; the README does not, because the README is teaching the real workflow.
- **`select`, `export` and `report` are effectively undiscovered.** They shipped (README's
  status table marks all three **Shipped**) but the README quickstart stops at `value`.
  A user who quits after step 4 has never seen the rejection log, the portfolio, or the
  one-page verdict — which is the part of the product that is not an eval harness.
- **There is nothing runnable to point at.** `docs/quickstart.gif` shows the loop; you
  cannot run a GIF. There is no `examples/` directory in the tree (DESIGN.md:261 anticipates
  one; it does not exist).

`kno demo` seeds the scenario, runs all five stages against `fake:`, spends nothing, and
leaves the input files on disk so the next thing the user does is edit them.

## Design

### One entry point, and why the alternative is rejected up front

The mandated rejection first, because it shapes everything below. The obvious alternative is
`kno init --demo` to write the files plus a `--demo` flag on `baseline` and `value` to fill
in the rest. **Rejected.** Three reasons, in damage order:

1. **Two surfaces telling one story is drift by construction.** `kno init` merges into an
   existing `kno.yaml` (`cli/init.go:118`), pre-fills from the file and never from defaults,
   and refuses a newer-versioned file even under `--force`. A `--demo` mode inside that has
   to answer "does the demo's `agent: fake:` overwrite the user's `agent: openai:gpt-4.1`?"
   — and every answer is wrong. Yes destroys their config; no makes `--demo` a lie.
2. **A `--demo` flag on `baseline` is a spend-path flag.** `baseline` resolves config and env
   (`cli/baseline.go:108-113`, `applyFileAndEnv`), so `--demo` would sit downstream of
   `KNO_AGENT` and `kno.yaml`'s `agent:` key. A demo flag that can be pointed at
   `openai:gpt-4.1` by an environment variable the user forgot about is prime directive 4
   with a friendly name.
3. **It does not solve the actual problem.** The run-ID copy step survives: `kno baseline
   --demo` still prints a random run ID that `kno value --demo` still needs.

`kno demo` is one command, one code path, one scenario, and it reads no configuration at all.

### What it runs

The scenario is **the tape's scenario, verbatim** — twelve Cases across four tags
(`refunds`, `shipping`, `account`, `billing`) and three knowledge Assets
(`refund-policy-v3`, `ship-promise`, `brand-guide`). Not a new scenario:
`tapes/quickstart.tape` carries it, along with a comment block explaining exactly why the
numbers look the way they do. Two scenarios telling one story is the same drift this plan
rejects above, one level down. The tape is re-recorded to drive `kno demo` (see Docs impact),
leaving exactly one demo scenario in the tree.

**Twelve, corrected from nine after implementation measured it** *(F4)*. This plan's first
draft said nine, inheriting the tape — and the tape was wrong. The `kno demo` implementation
workstream ran the planned scenario against a real binary before writing code and found that
the golden-pinned honesty epilogue below could not be true: every Asset rendered `—` and
"sample too small or ragged to form an interval", and `select` rejected on `underpowered`
rather than `no-effect`. Traced: the split is id-keyed, so nine Cases put six in dev;
`value.DefaultControlReserve` is 0.3, `int(6 * 0.3)` is one control Case, and
`interval.compute` returns nil below n=2 — after which the underpowered gate nulls the GOAL
interval too, though the goal arm's own pairs would have produced one. Twelve Cases put eight
in dev, reserving two, which is the minimum that computes: measured output is
`+0.0000 [-0.3960, +0.3960]` with `select` rejecting on "delta 0, CI crosses zero".

The count is therefore load-bearing, not decorative, and shrinking it silently reverts the
epilogue to a lie. The tape's own comment block now records this (PR #143), and the
defaults-parity discipline of *(F1)* applies to the fixture size too: the golden that pins
the epilogue is what fails if someone trims a Case.

Twelve still shows the warning the demo wants on its first screen: at
`split.DefaultHoldoutFrac` (0.2) it splits visibly, four Cases are held back, and the holdout
lands below `split.MinHoldout` (20), so `Counts.Underpowered()` fires and the baseline
renderer prints the too-small-holdout warning (`cli/render.go:188`).

The five stages, with the exact flags the commands declare:

```
kno baseline --evals <dir>/cases.jsonl --agent fake: --goal exact-match \
             --db <dir>/kno.db --run-id demo-baseline
kno value    --evals <dir>/cases.jsonl --pool <dir>/pool.jsonl \
             --baseline-run-id demo-baseline --db <dir>/kno.db --run-id demo-value
kno select   --value-run-id demo-value --pool <dir>/pool.jsonl \
             --max-context-tokens 5000 --max-training-examples 10 --max-cost-usd 1 \
             --db <dir>/kno.db --run-id demo-select
kno export   --select-run-id demo-select --pool <dir>/pool.jsonl \
             --destination tuning_set --out <dir>/tuning.jsonl \
             --db <dir>/kno.db --run-id demo-export
kno report   --value-run-id demo-value --select-run-id demo-select --db <dir>/kno.db
```

**In process, through the same run functions the commands call** (`runBaseline`, `runValue`,
`runSelect`, `runExport`, `runReport`), with the flag structs constructed literally in
`cli/demo.go`. Not by shelling out to `os.Args[0]` (a demo that depends on the binary being
on `$PATH` breaks for `go run ./cmd/kno`), and not by re-implementing the pipeline (a second
implementation of the loop is a second thing to keep correct). Constructing the flag structs
directly is also what makes the config bypass below structural rather than conventional — and
it carries one hazard that the first draft got backwards, handled in "Flag defaults are not
inherited" below *(F1)*.

### Fixture location: `go:embed`, and the two rejected alternatives

The two JSONL files live at `cli/demodata/cases.jsonl` and `cli/demodata/pool.jsonl`, embedded
into the binary with `//go:embed demodata` in `cli/demo.go`. **This is the first `go:embed` in
the tree** — `grep -rn "go:embed"` returns nothing today — so it is a new pattern and gets a
defence:

- **vs. generating the files from Go string literals into a temp dir.** Rejected: it buries a
  user-facing file format inside Go source, where nobody reviewing a Case can read it as the
  file it is, and where the tape and the README would each hold their own copy of the same
  nine lines. As `.jsonl` files on disk they are diffable, copy-pasteable into the docs, and
  `make update-golden` can pin them.
- **vs. shipping them in `examples/` and reading from the repo.** Rejected: the supported
  install paths are Homebrew, `install.sh`, and `go install` (README:83). None of them
  produce a repo checkout. A demo that requires a `git clone` is not a demo.

Embedding costs about 1.5 KB in the binary and makes the demo work with no network, no
checkout, and byte-identical content across every install — which is what lets the golden
test in the test plan mean anything.

### Where it writes, and what it says afterwards

**A directory in the user's cwd, `./kno-demo/` by default, overridable with `--dir`.** Not a
temp dir, not the cwd root.

- **Not a temp dir**: half of the demo's value is the second thing the user does, which is
  open `kno-demo/cases.jsonl` and replace nine lines with their own. A path under
  `/var/folders/...` is unmemorable, is not where they are working, and is subject to OS
  cleanup on a schedule nobody knows.
- **Not the cwd root**: the demo writes four files plus a SQLite DB. Scattering `cases.jsonl`,
  `pool.jsonl`, `tuning.jsonl` and `kno.db` into whatever directory the user happened to be
  in is a mess they have to clean up by hand, and `kno.db` in particular would collide with
  the `--db` default (`kno.db`) that every real command uses.

**It does not clean up, and therefore takes no `--keep` flag.** The epilogue names the
directory and says `rm -rf kno-demo` removes it. A demo that deletes its own artifacts leaves
the user with nothing to poke at — which is the same failure as writing to a temp dir, paid
for with a flag.

**DB**: `<dir>/kno.db`. Inside the demo directory, never the user's `./kno.db`. This also
means the demo's traces (which `kno purge` exists for) are removed by the same `rm -rf`.

**Epilogue**, printed after `report`, and not optional:

```
Demo complete — nothing was spent, and nothing was sent anywhere.

  kno-demo/cases.jsonl   9 eval Cases (6 dev, 3 held back)
  kno-demo/pool.jsonl    3 candidate Assets
  kno-demo/tuning.jsonl  the exported tuning set
  kno-demo/kno.db        every run, score and trace
  kno-demo/.gitignore    written by the demo, so this directory stays out of `git status`

Why the numbers look like this:
  score 1.000    `fake:` answers every Case with what the Case expects, by construction.
  deltas 0.0000  injecting an Asset cannot change a deterministic answer, so no Asset
                 measured any effect. The intervals are real; the effects are zero.
  portfolio empty  every corrected interval crosses zero, so nothing earned its place.
                 "Include nothing new" is a legal, first-class outcome, and the
                 rejection log says why for each Asset.

Now do it with your data:
  1. edit kno-demo/cases.jsonl — one scoreable interaction per line, with a stable id
  2. kno baseline --evals kno-demo/cases.jsonl --agent openai:gpt-4.1 --max-cost-usd 2.00

kno.yaml and KNO_* were not read: the demo is pinned to `fake:` so it cannot bill anyone.
Remove everything with: rm -rf kno-demo
```

The three "why" lines are the whole honesty design and they are load-bearing. `fake:`
(`adapters/agent/fake/fake.go:47`) echoes `Case.expected` when `Options.Answer` is nil, and
`cli/agentwiring.go:177` constructs it with `fake.Options{}` — so the score is 1.000 by
construction. Injection goes through `contextAgent.Invoke`, which records the injection and
then **delegates unchanged** (`fake.go:217`) — so the treatment arm and the control arm
produce identical output and every delta is exactly 0.0000. The empty portfolio is not a
degenerate case to be engineered around: it is the arithmetically correct answer, and it is
the one screen in the demo that shows the product refusing to recommend something.

`--json` carries the same three sentences in a `notes` array. A machine consumer that reads
`"score": 1.0` with no caveat has been misled by omission, and the human/JSON equivalence
golden pins that they stay in step.

### Consent and the budget guard: exercised, not bypassed

**Exercised.** The demo constructs the same `budget.Guard` and the same `confirmFunc`
recorder that `runBaseline` builds for any run, and it does **not** pass `--yes`.

The chain, verified end to end rather than assumed: `fake.Agent.Spends()` returns false
(`fake.go:248`, the one place core's "assume it spends" default is overridden), and
`fake.Agent` implements no `WorstCase()`, so it is **not** a `core.Estimator` —
`planningCostPerCall` therefore falls through to
`EstCostPerCallUSDMicros = usdToMicros(f.costPerCall)`, and for a literal flag struct whose
`costPerCall` is at Go's zero value that is 0. `consentDialog` computes its bounded quote
before the TTY check matters, and `est.CostUSDMicros < usdToMicros(1.00)`
(`confirmThresholdUSD`, `cli/render.go:25`) holds, so the dialog returns early without
prompting (`cli/consent.go:116`) whether or not stdin and stdout are terminals. This is not
a P0 and needs no mitigation; it needs the test in the test plan that keeps it true.

The property that matters: **the demo sets no bypass flag.** If anyone ever wires a spending
agent into this path, the guard fires and the prompt appears, rather than a `--yes` sitting
in the code silently pre-approving it. A test asserts the demo's flag structs have `yes` false.

### Configuration: not read, structurally

`kno demo` does not call `loadConfigFile` and does not call `applyFileAndEnv`. The flag
structs are literals. This is the money-safety decision and it is worth being blunt about:
`configSpecs` (`cli/config.go:86`) maps `KNO_AGENT` and `kno.yaml`'s `agent:` onto the
`--agent` flag, so a demo that resolved configuration the way `baseline` does would run the
demo against whatever provider the user last configured, with their key, and bill them for
the privilege of being shown around.

A user with an existing `kno.yaml` gets exactly the same demo as a user with none, plus the
one epilogue line saying so. Nothing about their `kno.yaml` changes, and `--config` is not
accepted.

### Flag defaults are not inherited, and the compiler will not tell you *(F1)*

The first draft claimed that a new required flag would show up "as a compile-time struct
field, not a silent divergence". **That is false, and it is the highest-damage error in this
plan.** A literal `baselineFlags{...}` that omits a field takes **Go's zero value**, not the
value `flags.Float64Var` registered with cobra. The compiler enforces nothing: adding a field
to a struct does not break a keyed composite literal, and adding a flag registration does not
touch the struct at all.

The hazard is concrete, not theoretical. `--holdout-frac` is registered as
`flags.Float64Var(&f.holdoutFrac, "holdout-frac", jsonl.DefaultHoldoutFrac, ...)` = 0.2
(`cli/baseline.go:130`). If `cli/demo.go` does not set `holdoutFrac` explicitly, the demo runs
with the **holdout disabled**, which silently breaks acceptance criterion 5 — the
too-small-holdout warning is the demo's first screen — with no compiler signal and no test
signal short of someone noticing a line missing from the transcript golden. The same class of
divergence exists for every non-zero registered default the demo does not hand-copy:

| Command | Flag | Registered default | Zero-value literal gives |
|---|---|---|---|
| `baseline`, `value` | `--agent` | `"fake:"` | `""` — agent resolution fails |
| `baseline`, `value` | `--goal` | `"exact-match"` | `""` — goal resolution fails |
| all five | `--db` | `"kno.db"` | `""` |
| `baseline` | `--holdout-frac` | `jsonl.DefaultHoldoutFrac` (0.2) | `0` — **holdout disabled** |
| `baseline` | `--temperature` | `math.NaN()` (`baseline.go:167`) | `0` — sends a temperature instead of leaving it unset |
| `value` | `--routing-seed` | `1` (`value.go:113`) | `0` — a different routing draw |

The demo happens to pass `--agent`, `--goal` and `--db` explicitly, which is exactly why the
danger is easy to miss: the three that would fail loudly are set, and the three that fail
quietly are the ones a reader does not think about. And the list drifts: every flag added to
any of the five commands after this merges is a new opportunity for the same bug.

**Mechanism: a defaults-parity test** (`cli/demo_defaults_test.go`), added as acceptance
criterion 19. For each of the five commands it constructs the real cobra command, walks
`cmd.Flags().VisitAll()`, and compares each flag's `DefValue` against the corresponding field
of the demo's literal struct, rendered the same way. A flag whose default the demo neither
matches nor appears in an explicit, commented `demoOverrides` allowlist (`--evals`, `--pool`,
`--run-id`, `--db`, the budget flags, the stage-linking IDs) fails the test, naming the flag
and both values. A newly registered flag with a non-zero default fails on the day it is
added, which is the only day the fix is cheap.

**The alternative, and why it lost.** Constructing the structs programmatically *from* the
registered defaults is strictly stronger — it cannot drift, because there is one source of
truth — but the defaults are written into a closure-local `f` inside each `newXCmd()`
constructor, so it would require refactoring flag registration out of five command
constructors, four of which are spend paths, to serve a free demo. That is a larger blast
radius than the bug it prevents, and the extraction would itself need a test proving it stayed
faithful — i.e. this test anyway. Recorded here so the choice is a decision rather than an
omission; if registration is ever factored out for another reason, the demo should switch to
it and the parity test becomes the regression net for the extraction.

### Flags: the minimum surface

| Flag | Default | Why it exists |
|---|---|---|
| `--dir` | `kno-demo` | The one thing a user might reasonably need to move (read-only cwd, a scratch path they already use). |
| `--force` | false | Re-running into a populated directory. See below. |
| `--json` | false | The repo-wide convention; every other command has it, and CI-shaped consumers exist. |

Nothing else. Explicitly **not** accepted, each for a reason:

- `--agent` — a demo against a real provider is a run, not a demo, and it spends.
- `--db` — the DB belongs inside `--dir`; a second path is a second thing to clean up.
- `--yes` — nothing prompts, and a bypass flag on a free path is a bypass flag waiting to be
  copied onto a paid one.
- `--keep` — nothing is cleaned up, so there is nothing to keep.
- `--config` — see above.
- `--run-id` — the fixed IDs are the point (they make the epilogue's follow-up commands
  copy-pasteable).

### Re-runnability

Run IDs are fixed strings: `demo-baseline`, `demo-value`, `demo-select`, `demo-export`.
Fixed so that the epilogue and the docs can name them, and so the golden test has stable
output. The consequence is that a second `kno demo` into the same directory hits
`store.ErrRunExists` (`store/sqlite.go:598`).

**The demo is not resumable and does not pretend to be.** A pre-flight check refuses a
`--dir` that already exists and is non-empty, with an Actionable naming `--force`:

```
error: kno-demo already exists and is not empty
  the demo writes a fixed set of files and fixed run IDs, so it cannot merge into a
  previous run
  fix: re-run with --force to replace it, or --dir to pick another directory
```

`--force` replaces the demo's own files and starts clean. Not "resume": there is nothing
worth resuming when the whole run is thirty free seconds, and a resumable demo would be a
second copy of the resume machinery exercised by nothing.

Deletion under `--force` is scoped twice over *(F2)*. The marker is the outer gate: the demo
refuses `--dir` values that resolve to the current directory, and refuses any existing
directory it cannot verify it wrote (checked by the presence of a `<dir>/.kno-demo` marker
file written on first run). `--force` on a directory without the marker is refused, naming the
marker. A `--force` that can `rm -rf` an arbitrary path because someone typo'd `--dir ~` is
the kind of bug that ends a project's reputation.

**The marker alone is necessary but not sufficient**, which the first draft missed. Once the
marker exists, "clear the directory" destroys anything the user has since put beside the
demo's files — a note, a scratch script, an edited copy of a Case — silently, and the demo
directory is precisely a place we are inviting people to work in. So `--force` deletes an
explicit allowlist of demo-owned names and nothing else:
`cases.jsonl`, `pool.jsonl`, `tuning.jsonl`, `kno.db` (plus `kno.db-shm` / `kno.db-wal`),
`.gitignore`, `.kno-demo`. Anything else in the directory is left untouched and **named** in
one line before the run starts (`kno-demo/notes.md left in place`), so a user is told rather
than surprised. A file the demo cannot delete (permissions) aborts before any stage runs.

**The demo writes its own `.gitignore`.** The repo's `.gitignore` covers `*.db` and
`training_set*.jsonl` but nothing that matches `kno-demo/{cases,pool,tuning}.jsonl` or
`.kno-demo`, so running the demo inside any git repository — which is where a new user will
run it — leaves four untracked files in `git status`. Ignoring them in *this* repo would help
only kno's own developers, so the demo instead writes `<dir>/.gitignore` containing `*` on
first run: self-contained, correct in every repository, and removed by the same `rm -rf`. It
is listed in the epilogue's file list and in acceptance criterion 1.

### Where the command lives

`cli/demo.go`, registered in `NewRootCmd` (`cli/root.go:127`) alongside the others. Flat, like
every existing command. `cli/demodata/` holds the two JSONL files.

## Acceptance criteria

Numbered, observable, checkable.

1. `kno demo` in an empty directory exits 0 and creates `./kno-demo/` containing exactly
   `cases.jsonl`, `pool.jsonl`, `tuning.jsonl`, `kno.db`, `.gitignore`, and `.kno-demo`
   (plus SQLite's `-shm`/`-wal` siblings while the DB is open) *(F2)*.
2. `kno-demo/cases.jsonl` is byte-identical to `cli/demodata/cases.jsonl`; likewise
   `pool.jsonl`. A golden test pins both.
3. The five stages run in order and each prints its own renderer's output; the transcript
   contains the baseline block, the value table, the select verdict, the export line, and the
   report page.
4. Reported spend is `$0.00` at every stage, and the process makes no network connection
   (asserted by a test that fails the run on any dial).
5. The baseline block reports `score 1.000` and the too-small-holdout warning (holdout of 3
   is below `split.MinHoldout` = 20).
6. Every Asset's delta renders `+0.0000` with a non-nil interval, and the selected portfolio
   is empty with a rejection reason recorded for each of the three Assets.
7. The epilogue prints after `report` and contains all three "why the numbers look like this"
   lines, the five file paths, and the `rm -rf` line.
8. `kno demo --json` emits one JSON document on stdout with no prose before or after it, and
   its `notes` array contains the same three honesty sentences as the human epilogue
   (equivalence golden).
9. A `kno.yaml` in the cwd declaring `agent: openai:gpt-4.1`, and `KNO_AGENT=openai:gpt-4.1`
   in the environment, change nothing: the run still uses `fake:` and still reports `$0.00`.
   The test asserts both, together and separately.
10. No demo code path passes `yes: true` or `jsonOut: true` into `confirmFunc` in a way that
    suppresses the guard; a test reads the constructed flag structs and asserts `yes == false`.
11. Re-running `kno demo` into the same directory exits non-zero with
    `errs.ErrInvalidInput` (exit code 1, per `errs.ErrInvalidInput.ExitCode == ExitError`)
    and a fix line naming `--force` and `--dir`.
12. `kno demo --force` into that same directory exits 0 and reproduces the byte-identical
    transcript of criterion 3 (durations elided).
13. `kno demo --force --dir <a directory with no .kno-demo marker>` is refused without
    deleting anything, naming the marker.
14. `kno demo --dir .` is refused.
15. Ctrl-C mid-demo exits 4 (`errs.ExitInterrupted`) and leaves the directory in place; no
    partial file is presented as complete.
16. `kno demo --help` mentions `fake:`, "spends nothing", and the default directory.
17. `kno demo` never reads `--config` or any `KNO_*` variable: a test with every `KNO_*` key
    in `configSpecs` set to a poison value produces the identical transcript.
18. Wall-clock for the whole demo is **measured once the five stages are wired, recorded in
    the PR description, and pinned there as the regression baseline** *(F3)*. No wall-clock
    number ships as a blocking gate in this plan. The first draft asserted "under 30s on CI
    hardware", which was never measured: twelve Cases against `fake:` with SQLite writes should
    be sub-second, but `value`'s per-Asset measurement count is the unknown, and a plan whose
    sibling condemns invented thresholds must not ship an unverified one of its own. Spiking
    it in Phase 0 would mean writing the implementation this plan is not allowed to write, so
    the criterion is measure-then-pin: if the measured figure is uncomfortable, that is a
    design finding to raise before merge, not a number to have guessed.
19. **Defaults parity** *(F1)*: for each of the five commands, every registered flag default
    (`cmd.Flags().VisitAll()` → `DefValue`) either matches the corresponding field of the
    demo's literal struct or appears in the commented `demoOverrides` allowlist. A test fails
    on any other divergence, naming the flag and both values. Deleting `holdoutFrac` from the
    demo's literal must fail this test *and* criterion 5 — verified by removing it.
20. `kno demo --force` into a marked directory containing a user-created `notes.md` leaves
    `notes.md` byte-identical, names it in the pre-run line, and replaces only the allowlisted
    demo-owned files *(F2)*.
21. The created directory contains a `.gitignore`; after a run inside a real `git init`
    repository in a temp dir, `git status --porcelain` reports no untracked demo files
    *(F2)*.

## Alternatives considered

**`kno init --demo` plus `--demo` flags on `baseline`/`value`.** Rejected — the mandated
rejection, argued in full at the top of Design. Summary: it puts a demo mode inside a config
merger that must then choose between destroying the user's `agent:` key and lying; it puts a
demo flag downstream of `KNO_AGENT` on a spend path; and it does not remove the run-ID copy
step, which is the actual friction.

**A shell script — `examples/demo.sh`, with `gum`.** DESIGN.md:261 anticipates exactly this
("gum used in `examples/` shell scripts so even the demo scripts feel polished"). Rejected
for the entry-point role: it is not installed by Homebrew or `install.sh`, it does not run on
Windows (a supported release target — `.goreleaser.yaml` builds windows/amd64 and arm64), and
it cannot be covered by `make check`, so it rots exactly like the docs it replaces. A polished
`examples/` script is a fine thing to have later; it is not the thing a new user runs first.

**Print the commands without running them (`kno demo --dry-run` as the only mode).**
Rejected: the friction being removed is not "I don't know which commands to type" — the
README already lists them. It is "I have to author two files and paste a run ID before
anything happens". A command that prints commands leaves both intact.

**Use `fake.Wrong(share)` so the baseline does not read 1.000.** `fake.Wrong`
(`fake.go:258`) is real, deterministic, and would produce a baseline below 1.000 with actual
failed Cases — which would move routing from `ModeAllDev` into `ModeTagOverlap`
(`core/value/route.go:611`), making the tag-routing story visible. Rejected anyway, and this
is the closest call in the plan: `contextAgent.Invoke` delegates unchanged, so **no
configuration of the fake can produce a non-zero delta**. `Wrong` buys a prettier baseline
number and zero additional truth, at the cost of a new CLI surface (a parameterised `fake:`
scheme) that exists only for the demo. The routing-mode story is told in the epilogue's
prose instead, where it costs nothing and cannot be mistaken for a measurement.

**A second scenario, distinct from the tape's.** Rejected: two demo scenarios in one repo is
the drift this plan's whole premise objects to, one level down. The tape is re-recorded
against `kno demo` instead.

## Edge cases

| Case | Behavior |
|---|---|
| `--dir` does not exist | Created with 0755; the marker and `.gitignore` are written first |
| `--dir` exists and is empty | Used as-is; marker and `.gitignore` written |
| `--dir` exists, non-empty, has the marker | Refused unless `--force`; `--force` replaces only the allowlisted demo-owned names and re-runs |
| `--dir` has the marker **and** a file the demo did not write | `--force` leaves that file untouched and names it in one line before the run — the marker proves the demo made the directory, not that it owns everything now in it *(F2)* |
| A demo-owned file cannot be deleted (permissions) under `--force` | Aborts before any stage runs, naming the path; nothing partially cleared *(F2)* |
| The demo runs inside a git repository | `<dir>/.gitignore` (`*`) is written on first run, so `git status` is unpolluted. The repo's own `.gitignore` covers only `*.db` and `training_set*.jsonl`, which is why this is the demo's job and not a repo-config change *(F2)* |
| `--dir` exists, non-empty, **no** marker | Refused **even with `--force`**, naming the marker — `--force` never deletes a directory the demo did not create |
| `--dir .` or a path resolving to cwd | Refused, unconditionally |
| `--dir` on a read-only filesystem | Refused at the marker write, before any stage runs, with the path in the message |
| Disk fills mid-demo | The failing stage's own error surfaces; partial files stay on disk and the epilogue does not print (an epilogue after a failure would claim a completed loop) |
| `kno.yaml` present in cwd | Ignored entirely; one epilogue line says so; the file is never read, written, or validated |
| `kno.yaml` present and **unreadable / newer-versioned** | Still ignored — the demo does not call `loadConfigFileAt`, so a config file this build cannot parse does not block the demo |
| `KNO_*` set to anything | Ignored; criterion 17's poison test pins it |
| Non-TTY stdin (`kno demo < /dev/null`) | Runs identically. Nothing prompts: the quote is $0.00, below the $1.00 threshold, and `shouldPrompt` is false anyway |
| Non-TTY stdout (`kno demo \| tee`) | Runs identically; output is the same plain text. No spinner, no redraw, no raw mode |
| CI environment | Same as non-TTY. `--json` is available for assertion; exit code 0 on success |
| Ctrl-C during a stage | Existing `Execute` signal handling applies: ctx cancels, the stage checkpoints, exit 4. A second Ctrl-C kills, per `restoreDefaultOnFirstSignal` |
| Ctrl-C between stages | Same; the demo checks `ctx.Err()` between stages and returns `errs.ErrInterrupted` |
| Holdout | Four of the twelve Cases are sealed at ingestion and nothing in the demo reads them — the demo runs no `validate`. A canary test asserts no holdout Case ID appears in any demo output |
| The user edits `kno-demo/cases.jsonl` then re-runs `--force` | `--force` restores the embedded files — `cases.jsonl` is demo-owned and on the allowlist. The epilogue's "now do it with your data" step names `kno baseline`, not `kno demo`, precisely so the user's edits are not clobbered by the demo, and files they add under new names survive *(F2)* |
| Someone "improves" the demo so a delta is non-zero | Acceptance criterion 6 fails. The criterion is the guard, and the comment in `cli/demodata/cases.jsonl` says why, mirroring the tape's comment block |
| The binary is `go run ./cmd/kno` | Works — the fixtures are embedded, not read from the repo |
| Two `kno demo` runs concurrently in the same cwd | Both target `kno-demo`; the second fails at the marker/non-empty check or at `store.ErrRunExists`. Neither corrupts the other's DB (SQLite WAL), and neither is silently merged |

## Test plan

Unit and golden, in `cli/` (the existing `run(t, args...)` harness in `cli/cli_test.go`):

- **Full-transcript golden**, human and `--json`, with run IDs already fixed and durations
  elided. This is the regression net: it fails if any of the five renderers changes shape,
  if the epilogue is dropped, or if a number moves.
- **Honesty goldens**: the three "why" lines present in both renderings; the
  human/`--json` equivalence test that the `notes` array matches the epilogue's sentences.
- **Money tests**: reported spend `$0.00` at every stage; `yes == false` in every constructed
  flag struct; a poison test setting every `KNO_*` key from `configSpecs` plus a `kno.yaml`
  declaring `agent: openai:gpt-4.1`, asserting an identical transcript.
- **No-network test**: the demo runs with a dialer that fails the test on any connection
  attempt. `fake:` makes no request, so this must hold; it is the assertion that stops a
  future "let's fetch the sample data" change.
- **Directory tests**: fresh dir; existing empty dir; existing dir with marker (refused,
  then `--force` succeeds); existing dir without marker (refused even with `--force`, and a
  sentinel file inside it still exists afterwards); marked dir containing a user file
  (`--force` succeeds, the user file survives byte-identical and is named in the output);
  `--dir .` refused; unwritable dir refused before any stage; `.gitignore` written and
  `git status --porcelain` clean in a real temp repository *(F2)*.
- **Defaults-parity test** *(F1)*: `cmd.Flags().VisitAll()` over all five commands against the
  demo's literal structs and the `demoOverrides` allowlist; a mutation test that drops
  `holdoutFrac` from the literal and asserts the parity test fails.
- **Idempotence**: `--force` twice produces byte-identical transcripts and byte-identical
  `tuning.jsonl`.
- **Interrupt**: cancel the context mid-`value`; assert exit 4 and that the epilogue did not
  print.
- **Holdout canary**: no holdout Case ID appears in stdout, `--json`, or `tuning.jsonl`.
- **Help snapshot**: substring assertions on `kno demo --help`, matching the existing
  convention in `cli/cli_test.go` (which asserts substrings, not full golden files).

**What FAILS if this regresses:** a non-empty portfolio (criterion 6) catches anyone
engineering the demo into looking impressive; a non-zero spend catches a real adapter being
wired in; the poison test catches config resolution creeping into the demo; the no-network
test catches a fetch; the equivalence golden catches the caveats being dropped from `--json`.

## Accepted risks

- **The demo's numbers are unimpressive, on purpose.** Score 1.000, deltas 0.0000, empty
  portfolio. A prospective user who does not read the epilogue may conclude the tool found
  nothing. Accepted: the alternative is a demo whose numbers are staged, and a staged demo is
  a promise the product cannot keep on the user's own data. The mitigation is that the three
  explanatory sentences are non-optional in both renderings and pinned by a golden.
- **`go:embed` is a new pattern in this tree.** One new toolchain behavior to understand, and
  the embedded files can drift from the tape's if someone edits one and not the other.
  Mitigated by the tape driving `kno demo` (so there is only one copy) and by the golden that
  pins the written files against the embedded ones. The build-system question is **settled,
  not outstanding**: neither `.goreleaser.yaml` nor the `Makefile` references embed patterns,
  archive inclusion lists, or `trimpath`/`ldflags` interactions with `//go:embed`, and
  embedding is a compile-time directive orthogonal to both. No build change is needed.
- **`--force` deletes files.** Scoped three ways: the cwd refusal, the `.kno-demo` marker
  check, and an allowlist of demo-owned filenames — the marker proves the demo created the
  directory, which is a weaker claim than owning everything currently in it *(F2)*. The
  residual risk is a user who drops the marker file into a directory that already contains a
  file named `cases.jsonl`; that is not a threat model this command can close.
- **The demo bypasses configuration, which is a second resolution path.** If `baseline` ever
  gains behavior that lives in config resolution rather than in `runBaseline`, the demo will
  not have it. Accepted deliberately — the alternative is a demo that can spend money.
  **The bound is a test, not the compiler** *(F1)*: literal flag structs take Go's zero value
  rather than each flag's registered cobra default, so divergence is silent by construction
  (`--holdout-frac`'s 0.2 becoming 0 is the worked example above). The defaults-parity test of
  criterion 19 is what converts that silence into a failing build, and it is the only thing
  that does. If that test is ever deleted or skipped, this risk goes back to being unbounded —
  which is the sentence a future reviewer should read before deleting it.
- **One more command on the root.** `kno --help` grows a line. Cheap, and `demo` is the line
  a first-time reader most wants.
