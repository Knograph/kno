# M2-11: making the adapters reachable

**Status:** Phase 0, draft 2 — revised after Phase 1 review returned **BLOCK** (5 P0s, all verified against the tree and all upheld)
**Repays:** [#37](../debt.md#37), [#42](../debt.md#42), [#44](../debt.md#44), [#47](../debt.md#47), [#54](../debt.md#54); **partly** [#46](../debt.md#46)
**Depends on:** M2-4, M2-6, M2-7, M2-8, M2-10 (all merged)

## 1. Problem

`cli/resolveAgent` returns an adapter for exactly one scheme:

```go
if parsed.GetScheme() == agentref.SchemeFake {
    return fake.New(fake.Options{}), parsed, nil
}
return nil, nil, errs.ErrCapabilityUnsupported.WithFix(
    "only `fake:` is available in this build; provider adapters land in the next milestone")
```

Everything M2-3 through M2-8 built — `openaicompat`, `anthropic`, the transport with its host and
redirect rules, the pricing table, retry and rate-limit handling — **is unreachable from the CLI.**
Every test that exercises it constructs the adapter directly in Go.

So M2-11 is not a wiring chore. It is **the first PR in which `kno baseline` can spend the user's
money**, and prime directive 4 says that path is the one we are most careful about. Framing it as
"CLI flags and docs" is how it gets reviewed as plumbing; it should be reviewed as the milestone's
second security boundary, the first having been the transport.

The corollary the first draft got wrong: **every latent defect on the real-provider path is
currently invisible, because every test in the tree runs a sub-second in-process fake.** Draft 1
scoped this PR by reading the ledger. Phase 1 found the most damaging item by reading the
executor. Both are now in scope.

| Entry | What is broken | Reachable before M2-11? |
|---|---|---|
| [#54](../debt.md#54) | The sink's recording deadline starts at **run start**, not at shutdown. Nothing sets `RecordGrace`, so it is 30s for the whole run | Only in principle — no run is slow enough |
| [#47](../debt.md#47) | Run-fatal provider failures classified per-Case: a wrong API key on a 10,000-Case run makes 10,000 requests | No |
| [#42](../debt.md#42) | The resolved-model resume gate is dead: `BaselineOptions.ResolvedModel` is caller-supplied and read before any request | No |
| [#46](../debt.md#46) | A priced-variant model is unpriced; a capped run errors every Case and reports "too many cases errored" | No |
| [#44](../debt.md#44) | Engine-chosen concurrency is recorded and emitted but no surface reads it back | Partly |
| [#37](../debt.md#37) | No OTel spans on adapter calls | No |

**The ordering consequence:** #54, #47, #42, and #46 are each a way the first real-spend run fails
badly. Shipping the wiring before them means the first PR that can spend money ships without the
stops that bound it.

## 2. Design

### 2.0 The split

Three PRs. The boundary is chosen so that **nothing that can spend money merges before the guards
that bound the spend.**

| PR | Scope | Repays | Can spend money? |
|---|---|---|---|
| **11a** | Sink-deadline fix; run-fatal escalation and its four consumers | #54, #47, #42, #46 (refusal shape) | No |
| **11b** | Adapter wiring, flag surface, price override, consent, capability matrix, concurrency report | #44, #46 (rows) | **Yes** |
| **11c** | OTel spans + vhs tape | #37 | Unchanged from 11b |

Docs ride in the PR that changes the behavior, per CLAUDE.md — there is no trailing docs PR.

### 2.1 (11a) The sink's deadline is a shutdown bound applied from run start — #54

**This is the finding that reorders the milestone, and it is not in draft 1 at all.**

`executor.Run` builds the sink's context once, before any work starts:

```go
// executor/executor.go:236
recordCtx, recordCancel := context.WithTimeout(context.WithoutCancel(ctx), opts.recordGrace())
```

`recordGrace()` defaults to **30 seconds** (`executor.go:84-89`) and **nothing in the tree ever
sets `RecordGrace`** — `core.Baseline` passes `Concurrency`, `ID`, `Skip`, and `IsFatal` only
(`core/baseline.go:441-455`). `sinkFunc` uses that context for the durable write
(`core/baseline_record.go:891`), and `store/sqlite.go` is `ExecContext` throughout.

**Concrete failure.** `kno baseline --agent anthropic:claude-opus-5 --evals 500cases.jsonl`. At
t=30s the first `RecordOutcome` returns `context deadline exceeded`, `sinkBroken` latches
(`executor.go:255-259`), and **every subsequent result is silently discarded** — no outcome row,
absent from `CompletedCases`, and re-paid on the next `--resume`. The run ends `FAILED` with a
message about recording. Real money, spent twice, for every run over half a minute.

The comment on the line is right about the *intent* — "the grace period bounds how long a hung
sink can delay shutdown" — and the implementation applies it to the whole run instead.

**Proposal.** Separate the two deadlines the one context is conflating:

- **During the run**: `recordCtx` is `context.WithoutCancel(ctx)` with **no** deadline. A sink
  that blocks forever is a real hazard, so each individual `SinkFunc` call gets its own timeout
  (`perRecordTimeout`, default 30s) — which bounds a hung sink without bounding the run.
- **At shutdown**: once the results channel is closing, the remaining drain is bounded by
  `RecordGrace` as documented.

Per-call rather than per-run is the whole fix: the hazard is *one* hung call, and the current code
mistakes a budget for a sum.

**Second-order effect on §2.2, which is why this must land first:** run-fatal escalation *increases*
the burst of results arriving at the sink during a drain. Shipping run-fatal on top of #54 makes
the loss window worse, not better.

### 2.2 (11a) Run-fatal escalation — #47

**The constraint that shapes this.** `core` cannot import `adapters`. Prime directive 3 is
absolute, so `IsFatal` cannot write `errors.Is(err, anthropic.ErrAuthentication)`.

**Draft 1 proposed a sentinel (`errs.ErrRunFatal`) that adapters wrap. That is wrong in both
possible orientations, and the tree already documents why.**

`errs.Actionable` has a **single** `wrapped error` slot and `Wrap` replaces it
(`core/errs/errs.go:169-215`). `ErrAuthentication` already spends that slot on the provider's
sanitized cause (`anthropic/errors.go:216`).

- **`ErrRunFatal.Wrap(ErrAuthentication…)`**: `errors.As(err, **Actionable)` returns the outermost,
  so `codeOf` (`baseline_record.go:927-931`) persists `"RUN_FATAL"` instead of the adapter's code
  in `Outcome.Err`, on the event stream, and in `--json`; `ExitCodeOf` and `renderError` read the
  wrong one. **This is verbatim the [#39](../debt.md#39) defect**, which was found empirically and
  is documented at `anthropic/errors.go:79-90`.
- **`ErrAuthentication.Wrap(ErrRunFatal…)`**: `Actionable.Error()` inlines the chain
  (`errs.go:179-195`), producing a doubled `fix:` block — and there is nowhere left for the
  provider's cause, because the slot is taken.

**Revised proposal: the `retryAfterError` shape, which is the tree's own proven pattern.**

```go
// core/errs — declared where core can see it, satisfied structurally.
// core asserts: interface{ RunFatal() bool }

// adapters/agent/anthropic
type runFatalError struct{ *errs.Actionable }

func (e *runFatalError) RunFatal() bool { return true }

// Unwrap returns the embedded Actionable rather than the Actionable's own
// cause — without this the PROMOTED Unwrap jumps past it and
// errors.As(err, **errs.Actionable) answers false. See debt #39.
func (e *runFatalError) Unwrap() error { return e.Actionable }
```

Zero message change, no second `wrapped` slot, and it matches `retryAfterOf` and `billedCostOf`
— the two assertions `core` already declares. `core` gains `runFatalOf(err) bool` beside them.

**Per-instance at the classification site, never on a sentinel.** `Actionable.Is` compares by
**`Code`** (`errs.go:205-215`), and the spend-cap 429 comes back as `ErrProvider` — a code shared
with a dozen unrelated terminal errors (`anthropic/errors.go:174-179`). Escalating on the sentinel
would make every provider error run-fatal.

**The conditions.** Draft 1 named three; the review found three more that satisfy the same
"cannot change within a run" test:

| Condition | Where | Why it cannot change within a run |
|---|---|---|
| Rejected credential (401/403) | `anthropic.ErrAuthentication`, `openaicompat.errorFor` | The key is read once at construction |
| Spend-cap 429 (`enforced_spend_limit_reached`) | `anthropic/errors.go:111` | The provider's own cap; waiting cannot clear it |
| Refused destination / key-binding mismatch | `transport.ErrRefusedDestination`, `ErrKeyBinding` | Fixed by config, read once |
| **400 `selfSetSpendLimit`** | `anthropic/errors.go:238-241` | The code's own fix line says *"retrying will not clear it"* |
| **402 Payment Required** | `anthropic/errors.go:220-223` | An unpaid account does not become paid mid-run |
| **404 model-not-found** | `anthropic/errors.go:225-229` | A typo'd model name errors all 10,000 Cases |

**Deliberately NOT escalated:** a plain 429, a 5xx, a truncation, a refusal. Escalating any
converts a recoverable run into a dead one — strictly worse than the per-Case handling they have.
(Phase 1 confirmed this list is right; no change.)

**Proto change, and draft 1 said there was none.** `sinkFunc` uses `draining` as the discriminator
for the orphan reason:

```go
// core/baseline_record.go:851-855
reason := ORPHAN_REASON_CANCELLED
if draining.Load() { reason = ORPHAN_REASON_BUDGET_EXCEEDED }
```

A run aborted by a rejected credential would report, for every in-flight charged Case, *"The cost
or call cap could not admit another attempt."* [#52](../debt.md#52)'s repayment text exists
precisely because *"a run stopped by a human is not a run that ran out of money"*; run-fatal is a
third case. **`OrphanReason` gains `ORPHAN_REASON_RUN_FATAL`** — additive, `buf breaking` clean —
and the discriminator becomes a three-valued reason rather than a bool.

**Exit code: `ExitError`, which is `1`.** (Draft 1 wrote "(2)"; `2` is `ExitBudgetStopped`,
`errs.go:19-26`. The reasoning was right, the number was wrong, and exit codes are a post-1.0
covenant.) No new code: the CLI grammar's codes are about what the user does next, and "fix your
config and re-run" is the same next step as every other `ExitError`.

### 2.3 (11a) The unpriced refusal becomes run-fatal — #46 (refusal shape only)

**Draft 1's design was unimplementable and its escape hatch was a dead end the tree had already
removed once.** Both findings are upheld:

- `checkFeasible` has no Case and never calls `Estimate`. Its only price signal is
  `planningCostPerCall()`, and when a cost cap is set `validate` has already guaranteed
  `EstCostPerCallUSDMicros > 0` (`core/baseline.go:496`) — so the signal draft 1 needed **cannot
  appear at the place draft 1 put the check.**
- `--cost-per-call-usd` does **not** override an `Estimator` (`core/baseline_budget.go:45-49`), and
  `unpriceable`'s own godoc records that advertising it *"would send the user down a dead end —
  which the first version of this message did"* (`baseline_budget.go:96-99`). Draft 1 reintroduced
  it verbatim, in the fix line and in the edge-case table.

**Revised proposal: keep the refusal where the adapter already knows the answer, and make it
run-fatal.** `errUnpriceable` already exists as a sentinel, already distinguishes "refused before
any call" from "failed after a paid call" (`baseline_budget.go:90-95`), and is already returned
before `Authorize`. Wrapping it run-fatal means the **first** Case refuses and the run ends once,
with a message about pricing — instead of 10,000 Cases erroring into a verdict that names nothing
about pricing.

No new Ring-0 method, so no public-Go-API change. This is strictly cheaper than draft 1 and it
reuses the machinery §2.2 is building anyway.

**The real escape is a per-token override, not a per-call scalar.** `pricing.EstimateWithPrice`
exists for exactly this and says so: *"It exists for the price-override flags the plan schedules
for the CLI wiring PR"* (`pricing/estimate.go:112-114`). 11b adds `--price-input-per-mtok` /
`--price-output-per-mtok`, routed through it. The fix line names those, and **not**
`--cost-per-call-usd`.

**#46 is only PARTLY repaid, and draft 1 was wrong to claim it whole.** The entry's deferred item
is *"variants have no rows"*, trigger *"before the first tagged release"*. This PR changes the
shape of the refusal and adds an override; it adds no rows. The rows are still owed, from a human
reading the provider's published rates. Claiming otherwise would be the same false repayment
[#42](../debt.md#42)'s own text records and corrects.

### 2.4 (11a) The resolved-model gate moves to first-response time — #42

Today `checkResumable` compares `run.case_execution.resolved_models` against
`BaselineOptions.ResolvedModel`. The option is caller-supplied and read at `openRun` **before any
request**, so the only value it could ever hold is one a previous run recorded — the check
comparing a value to itself.

**Proposal.** Delete `BaselineOptions.ResolvedModel`. Move the check to the first response that
reports a model. Three corrections from review:

**(a) State placement.** Not a field on `BaselineOptions`: every method on it has a **value
receiver**, so `opts` is copied per call and a `sync.Once` field is a `go vet` copylocks failure
with `govet` in the lint bundle. The state is a `sync.Once` plus the recorded set declared in
`Baseline` and captured by the closure — the same shape as `var draining atomic.Bool`
(`core/baseline.go:437`).

**(b) The gate must not discard the answer.** Draft 1 had the gate return an error from the
response path. That routes a **paid, scoreable** Case through `workFunc`'s error path and records
it as an agent error — the identical mistake `SettlementOvershoot` already fixed once
(`baseline_invoke.go:157-162`). Revised: the Case is **scored and recorded normally**, and the
abort is triggered separately. We paid for that answer; throwing it away buys nothing.

**(c) `checkResumable` is called twice** (`baseline.go:341` probe, `baseline_run.go:33`). The
resolved-model arm is removed from both. `resolvedModelChanged`, `recordedModels`, and
`staleFix`'s `modelChanged` parameter move to the new gate rather than being deleted — the set-
membership logic and the "pin the model" fix line are both still correct, only relocated.

**Honest accounting of what the abort does not fix.** Review is right that draft 1 understated it.
`IsFatal` is consulted *after* the result is on the channel, and `cancel()` reaches other workers
asynchronously (`executor.go:305-315`), so up to `concurrency-1` further Cases can be recorded
under the new model. The run is left as a baseline whose `AggregateScore` blends two models.
`incomplete_reason` says so in prose and the fix line says re-run without `--resume`.

**A machine-readable "unusable as a reference" marker is deliberately NOT added here.** There is no
consumer: the first stage that reads a Baseline as a reference is Valuation, which does not exist.
Adding the field now is dead code that lands ahead of its reader — the exact trap #42 records and
this plan is repaying. New ledger entry, triggered to the first consuming stage.

### 2.5 (11b) Consent, which currently does not happen for the case we know least about

**Prime directive 4 is violated on today's `main` the moment a real adapter is reachable**, and
draft 1's §2.4 blessed the path. Verified:

1. Unpriced model, no cost cap, no scalar → `estimate()` takes the `err != nil && !capped` arm and
   returns the scalar, which is `0` (`baseline_budget.go:62-65`).
2. `planningCostPerCall()` → `WorstCase()` is `{}` → falls back to the scalar → `0`.
3. `confirmRun` returns `nil` **before ever calling `PreConfirm`**:
   `if remaining <= 0 || perCall <= 0 { return nil }` (`baseline_budget.go:128-131`).
4. So `Guard.confirmed` stays false, and the per-operation prompt needs
   `est.CostUSDMicros >= threshold` with `est` at `0` (`budget/budget.go:259`).

`kno baseline --agent anthropic:claude-opus-5-fast --evals 10k.jsonl` makes **10,000 real calls
with no prompt, no printed figure, and no `--yes`.** The asymmetry is backwards: a *priced* model
with no cap does prompt, because `WorstCase × remaining` crosses the $1.00 threshold. The one case
where we know least about the cost is the only one that skips consent.

**Proposal.** `perCall <= 0` stops being a silent pass. When the per-Case cost is *unknown* (as
opposed to *known to be zero*, which is what `fake:` legitimately is), the run quotes what it does
know — "N Cases, per-Case cost unknown for `<model>`" — and requires confirmation. The two states
are distinguishable: `fake:` is not an `Estimator`, an unpriced provider model is an `Estimator`
that returned `ErrUnpriced`.

**And `--yes` must print what it is consenting to.** `confirmFunc` today always declines
interactively (`cli/render.go:104-116`, *"the huh prompt lands with the TUI"*), so 11b's only
usable real-provider invocation is `--yes` — which returns true immediately and prints nothing.
Shipping a money path whose entire consent surface is a silent blanket flag is not defensible.
11b prints the estimate under `--yes`, unconditionally, before the first call. The interactive
prompt still waits for the TUI; this is the honest interim.

### 2.6 (11b) The flag surface

Corrected against the adapters and the transport. Draft 1 invented one flag, misnamed another that
already ships in error text, and omitted four real controls.

| Flag | Env mirror | Notes |
|---|---|---|
| `--base-url` | `KNO_BASE_URL` | **Composed into the `AgentRef` and parsed by `agentref.Parse`** — see §2.7 |
| `--allow-insecure-base-url` | `KNO_ALLOW_INSECURE_BASE_URL` | `Policy.AllowInsecureHTTP`. Off by default |
| `--allow-private-address` | `KNO_ALLOW_PRIVATE_ADDRESS` | `Policy.AllowPrivateAddress`. **Missing from draft 1**, and without it the headline cookbook recipe cannot reach a local vLLM or Ollama. Link-local stays unreachable and is not opt-in-able (`destination.go:56-62`) |
| `--key-env` (repeatable) | — | `host=ENV_VAR`. **Draft 1 called this `--key-binding`, which is invented**; four shipped sites name `--key-env`, including a test that asserts on it (`openaicompat/misbehaving_test.go:361`). Keys are the stated env-mirror exception |
| `--max-output-tokens` | `KNO_MAX_OUTPUT_TOKENS` | Generation ceiling and a pricing input |
| `--max-prompt-bytes` | `KNO_MAX_PROMPT_BYTES` | Governs `WorstCase`, therefore concurrency and the consent quote |
| `--temperature` | `KNO_TEMPERATURE` | Capability-checked at construction |
| `--seed` | `KNO_SEED` | `openaicompat` only |
| `--system` | `KNO_SYSTEM` | |
| `--generation-params` | `KNO_GENERATION_PARAMS` | Override for the per-model answer (`openaicompat/config.go:107-113`); load-bearing because nothing checks `Capabilities()` — see §2.9 |
| `--use-legacy-max-tokens` | `KNO_USE_LEGACY_MAX_TOKENS` | llama.cpp, LM Studio, older self-hosted |
| `--price-input-per-mtok` | `KNO_PRICE_INPUT_PER_MTOK` | Per-token override via `EstimateWithPrice` (§2.3) |
| `--price-output-per-mtok` | `KNO_PRICE_OUTPUT_PER_MTOK` | " |
| `--timeout` | `KNO_TIMEOUT` | Per-call deadline |

**`--allow-non-default-host` is removed.** Draft 1 claimed *"the transport refuses otherwise"*.
No such refusal exists: `Policy` has `AllowInsecureHTTP` and `AllowPrivateAddress` only
(`destination.go:52-63`). What is scoped to the default host is the *default key*
(`keybinding.go:127-140`). The flag was a no-op or an invented refusal.

**`--cost-per-call-usd` keeps its current meaning and gains an honest help string**: it applies
only when the Agent is not an `Estimator` (`exec:`, `fake:`). For a provider model the override is
per-token. Draft 1 had this backwards.

**`validate` must change.** It refuses **any** cost cap without `--cost-per-call-usd`
(`baseline.go:496`), so the flagship invocation `--agent anthropic:claude-opus-5 --max-cost-usd 5`
is refused today even though the adapter prices every Case perfectly — and the scalar the user is
forced to supply is then ignored. Revised: the requirement applies only when the Agent is not an
`Estimator`.

**Precedence:** flag beats env beats default, matching the rest of the CLI. Documented, and table-
tested per variable.

### 2.7 (11b) `--base-url` goes through `agentref`, or it is a second way a key reaches the record

`openaicompat.Options.Ref`'s godoc names this hazard exactly: a parsed ref rather than a model
string plus a URL string, because *"agentref is where the credential-in-a-URL and control-character
refusals live, and a second entry point that skipped them would be a second place for a key to
reach the Run record"* (`config.go:72-78`).

So `--base-url` composes into the `AgentRef` and is parsed by `agentref.Parse`. One validator, one
entry point.

**And userinfo is not the whole hazard.** `Run.agent.base_url` is persisted and emitted on
`RunStarted` (`baseline_run.go:44`, `baseline_record.go:445`), and `RedactURL` scrubs **userinfo
only** (`transport/redact.go:56-64`). A query-string credential —
`https://gw.example/v1?api_key=sk-…`, the form several gateways use — is refused by nothing,
persisted in SQLite, put on the event stream, and printed in `--json`. Path-embedded keys are the
same shape.

11b extends the redaction rule to query parameters whose name matches a credential-shaped key
(`api_key`, `key`, `token`, `access_token`, `password`, case-insensitive), refuses them in
`agentref.Parse` the way userinfo is refused, and tests both — including that the *error message*
does not echo the value. The existing userinfo coverage at `destination.go:96-102` and
`agentref.go:240-243` is confirmed good and is not duplicated.

### 2.8 (11b) The concurrency report — #44

`Run.concurrency` is recorded and `ConcurrencyReduced` is emitted; no surface reads either back.

Draft 1 put the line only in the post-run report. **#44's own text names the prompt**: *"the
consent prompt quotes a run whose width has already been cut and does not say so; the prompt is the
natural place for the report."* Revised: the reduction appears in the **consent prompt** (where it
changes what the user is agreeing to), in the human report, and in `--json`.

`--json` gains **hand-written** fields, not the embedded `*knov1.ConcurrencyDecision`.
`cli/jsonreport.go`'s header is a scoped ADR-0001 exemption: the struct is hand-written *"so it
should not shift underneath them when the schema gains a field"*, and embedding the proto message
would emit `int64` fields as bare numbers — the exact divergence from the generated OpenAPI spec
ADR-0001 bans.

### 2.9 (11b) The capability matrix, and the command that is already named

**Draft 1's premise was false: `Capabilities()` is never called anywhere in `core`, `cli`, or
`executor`** — grep across non-test files finds only the three adapter implementations and the
interface declaration. `core/ring0.go:31-33`'s godoc is aspirational. The refusal that actually
exists is at **adapter construction** (`openaicompat/config.go:95-101`,
`anthropic/anthropic.go:130-135`), which is still before any spend, so the user-visible behavior is
fine — but the plan must not claim a mechanism that is not there.

**The command is `kno doctor`, not `kno agents`.** `errs.ErrCapabilityUnsupported.Fix` already
says *"run `kno doctor` to print the capability matrix"* (`errs.go:66`) and no such command exists.
Shipping `kno agents` would leave a shipped fix line pointing at nothing. Read-only, no spend,
rendered from `Capabilities()` at runtime and snapshot-tested — generated rather than handwritten,
because a handwritten matrix drifts silently and the whole point is that it is true.

(Phase 1 confirmed "agents" is *not* vocabulary drift — `Agent`/`--agent`/`AgentRef` are
established. The collision with the shipped `doctor` fix line is the real problem.)

### 2.10 (11c) OTel — #37

`--otel-endpoint` (mirrored `KNO_OTEL_ENDPOINT`), off by default. A span per stage, per adapter
call, per plugin invocation, correlated by run ID. **Spans carry IDs and metrics only** — never
Case input, never Response content, never the system prompt — asserted by an exporter that fails
on any attribute value containing a substring of the fixture's content.

**`otlptracehttp`, not `otlptracegrpc`.** `go.mod` has three direct dependencies today
(`go-cmp`, `goleak`, `protobuf`). The gRPC exporter pulls `grpc`, `grpc-gateway/v2`, `go-logr`,
`cenkalti/backoff`, and the SDK tree — roughly 15 modules, each needing the dependency-
justification paragraph CLAUDE.md requires. The HTTP exporter avoids grpc entirely and is the
cheaper design draft 1's Q4 did not consider; a build tag is a worse answer than not taking the
tree.

**`charmbracelet/log` is not in `go.mod` either**, and CLAUDE.md mandates it for structured
logging. §5's "logged at WARN once" has nothing to log through. 11c adds it, or 11c's warning is
routed through whatever the tree settles on — flagged rather than assumed.

`DESIGN.md:399` places OTel export at v0.3 while `CLAUDE.md` says tracing is built in. This PR
resolves it in CLAUDE.md's favor and edits `DESIGN.md`: the flag being off by default makes the two
compatible — instrumentation built in, export opt-in.

## 3. Alternatives considered

**A1 — One PR for all of M2-11.** Rejected. It merges the spend path and its guards, so the review
that would catch a missing guard is the same review checking a flag surface, a capability matrix,
an OTel dependency tree, and six ledger repayments.

**A2 — Wiring first, guards after.** Rejected, and Phase 1 verified the danger rather than taking
it on faith: with `--max-calls 1000` and a wrong key on `main`+11b-without-11a,
`invokeWithRetry` returns a non-retryable `ErrAuthentication` per Case, `invokeOnce` settles
`Spend{Calls: 1}` on the error path (`baseline_invoke.go:318-322`), and `IsFatal` matches only
`ErrBudgetExceeded` — so all 1000 calls are made and settled.

**A3 — A sentinel (`errs.ErrRunFatal`) instead of the interface assertion.** **Rejected in draft 2;
it was draft 1's proposal.** Both wrapping orientations are broken (§2.2), and a third defect
applies to both: `FromProto` rebuilds an `Actionable` with `Unwrap() == nil` and only the outermost
`Code` (`errs.go:249-265`), so a run-fatal error crossing the wire — a Ring-2 plugin agent, the api
SSE path — **silently loses its run-fatality**, and #47's sweep returns for plugin adapters. The
interface assertion has the same wire limitation, which is why §7 Q1 asks about the plugin boundary
explicitly.

**A4 — Keep the resume gate at `openRun`, CLI passes the recorded model back.** Rejected as
circular; confirmed by review.

**A5 — Refuse an unpriced model unconditionally.** Rejected: it makes table completeness a hard
dependency for every run, so a model shipped between two Kno releases is unusable rather than
merely unbounded. Confirmed by review.

**A6 — Draft 1's `checkFeasible` unpriced refusal.** Rejected as unimplementable (§2.3): the
signal cannot appear there.

**A7 — Add a Ring-0 `WorstCase() (budget.Estimate, error)` probe** so `core` can detect unpriced
up front. Rejected: `core.Estimator` is part of the stability-promised public Go API, and §2.3's
run-fatal refusal gets the same user-visible outcome — one refusal, before the second call — at
zero API cost.

**A8 — Set `RecordGrace` to a large value instead of restructuring (§2.1).** Rejected. It moves the
cliff rather than removing it: any run longer than the new value has the same silent-discard
failure, and the value would have to be guessed against eval-set size. The bug is that a shutdown
bound is applied to a run.

## 5. Edge cases

| Case | Mitigation |
|---|---|
| Run longer than 30s (§2.1) | Per-call timeout; the grace applies at shutdown. Test: a sink slower than the old grace, run longer than it, assert every outcome is durable |
| Sink genuinely hung on one call | Per-call timeout fires; `sinkBroken` latches as today |
| Run-fatal fires with N-1 Cases in flight | `draining` set; in-flight Cases settle; orphan reason is `RUN_FATAL`, not `BUDGET_EXCEEDED` |
| Run-fatal fires on an already-charged Case | Settles through `sinkFunc`'s retry-exhausted branch (M2-10d). Test asserts guard and store agree |
| Resolved-model gate fires | The Case is **scored**, not discarded. Up to `concurrency-1` further Cases are recorded under the new model — stated, not hidden. `incomplete_reason` names both models |
| Gate races: N workers respond simultaneously | `sync.Once` declared in `Baseline`, captured by the closure — never a field on `BaselineOptions` (copylocks) |
| Resume where the recorded set is empty | Nothing to compare; inert. Covered by `TestAnUnknownResolvedModelDoesNotBlockAResume` |
| Unpriced model + cost cap | Run-fatal refusal on the **first** Case. Fix line names the per-token override, **never** `--cost-per-call-usd` |
| Unpriced model, **no** cap, no override | Runs — but **takes consent first** (§2.5), quoting "N Cases, per-Case cost unknown" |
| Unpriced model, **call** cap only | Same: consent, then runs. The call cap needs no price |
| `--base-url` with a credential in userinfo | Already refused (`destination.go:96-102`, `agentref.go:240-243`), non-echoing. Not re-tested |
| `--base-url` with a credential in the **query string** or path | **New refusal** (§2.7). Test asserts the value is absent from the error, the Run record, and the event stream |
| `--key-env` naming an unset var, `anthropic`, default host | Refused at construction. No spend |
| `--key-env` naming an unset var, `openaicompat` | **Not refused today**: `connect` omits the `Authorization` header (`config.go:229-234`) and the provider 401s per Case. Now run-fatal, so it aborts once — but 11b should refuse it at construction. Ledgered if not fixed |
| `--key-env` naming an unset var, `anthropic`, **non**-default host | Deliberately permitted (`anthropic.go:333-338`): a non-Anthropic host may legitimately need no credential |
| `--temperature` unsupported by the model | Refused at **adapter construction**, not by a ring-0 check (§2.9) |
| OTel endpoint unreachable | Never fails the run. One WARN, not per span |

## 6. Test plan

**11a**
- **#54**: a sink slower than the old 30s grace, on a run longer than it, asserts every outcome is
  durably recorded and a resume re-pays nothing. Mutation: restore the run-scoped deadline; must
  fail with discarded outcomes.
- Each of the **six** run-fatal conditions ends the run early. **Assertion corrected for
  concurrency**: `IsFatal` fires after the result is on the channel and `cancel()` propagates
  asynchronously (`executor.go:305-315`), so at `DefaultConcurrency()` between 1 and 8 Cases will
  have been recorded. Two tests: `Concurrency: 1` asserts exactly `attempted == 1`; the concurrent
  case asserts `attempted <= concurrency && attempted < 50`. Draft 1's flat `attempted == 1` on a
  50-Case set is flaky by construction and CLAUDE.md's flaky policy forbids shipping it.
- A non-escalating error (plain 429, 5xx, truncation) does **not** end the run — the test that
  catches over-escalation, which is the more expensive direction.
- **The #39 inversion mutation**: rewrite `runFatalError` to drop the `Unwrap()` override; the
  persisted `Outcome.Err` code must stop being the adapter's, and the test must fail.
- The orphan **reason** on a run-fatal abort is `RUN_FATAL`, not `BUDGET_EXCEEDED`.
- Escalation is per-instance: a different `ErrProvider` with the same `Code` is **not** run-fatal.
  This is the test that catches `Actionable.Is`-by-Code over-matching.
- First-response gate: a fake reporting a changed model on Case 3 of 50 aborts; the Case is
  **scored**, not errored; `incomplete_reason` names both models. Mutation: pin the gate back to
  `openRun`; must fail.
- Fresh run observing two models is not refused.
- Draft 1's *"`BaselineOptions.ResolvedModel` is gone — a compile-time assertion via its absence"*
  is **deleted**. Nothing fails to compile because a field is absent once the only reference is
  removed. The `openRun` mutation is the one with teeth.

**11b**
- Consent: unpriced + no cap + no override **prompts**, and `--yes` **prints** the figure. Mutation:
  restore `perCall <= 0 → return nil`; must fail with a silent run.
- The three-condition unpriced matrix, written against §2.3's actual mechanism (draft 1's eight-row

- The refusal happens before any call — a store with zero outcomes and a guard with zero spend.

  the event stream. Extends the existing secrets scan to golden files.

  `Estimator`, and still refuses when it is not.

  creates is the one nothing covers today.

- Endpoint unreachable: run completes, one WARN.

## 7. Open questions for review

**Q1.** A run-fatal error crossing the plugin/API boundary loses its run-fatality — `FromProto`
rebuilds an `Actionable` with no chain and only the outermost `Code` (`errs.go:249-265`). Does
run-fatality need to be a field on the wire error, or is "Ring-2 plugin agents re-open #47" an
accepted risk until a plugin Agent exists?

**Q2.** Does a run-fatal abort need its own **event**, or is `RunFinished` + `RUN_STATUS_FAILED` +
the `Actionable` sufficient? §2.2 argues sufficient; the counter is that a `--json` consumer cannot
tell "aborted at Case 1 of 10,000" from "ran 1 Case and failed" without knowing the input size.
(11a now has a proto change regardless, so "we would rather not open the proto" is no longer an
argument either way.)

**Q3.** Should `openaicompat` refuse an unset `--key-env` var at construction (§5), matching
`anthropic`'s default-host behavior — or is proceeding unauthenticated legitimate for a
self-hosted endpoint that needs no key, making the 401 the correct signal?

**Q4.** `--price-input-per-mtok` / `--price-output-per-mtok` override the table. Same staleness
hazard Q2-of-draft-1 raised about the scalar: a stale override in a CI config misprices every run
after a model change. Should an override warn when the table *does* have a row that disagrees?

## 8. Rollback

11a and 11b are independently revertable **as long as `errUnpriceable`'s run-fatal wrapping and the
`runFatalOf` assertion both live in 11a** — draft 1's §8 claimed independence while §4 put
`errs.ErrUnpriced` in 11a and its consumer in 11b, which would have broken 11b's compile on a
revert. Corrected: 11a owns both sides of every seam it introduces.

Reverting 11b returns the CLI to `fake:`-only, which is `main` today — no data migration, no schema
change, no stored run becomes unreadable. 11c is a flag defaulting off. **11a's proto addition is
additive**, so a revert leaves old readers unaffected.

The one-way door is **11b's flag names**, which become the CLI covenant at 1.0. They now match the
names already in shipped error text (`--key-env`) rather than invented ones; pre-1.0 renames carry
a CHANGELOG migration note.
