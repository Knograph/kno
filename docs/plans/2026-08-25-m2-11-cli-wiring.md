# M2-11: making the adapters reachable

**Status:** Phase 0, draft 3 — two Phase 1 review passes, both **BLOCK**. Pass 1: 5 P0s, all verified
and upheld. Pass 2 (fresh reviewer, on draft 2): 4 P0s, all verified and upheld — including one that
showed a draft-2 *security* section rested on a false premise. Draft 3 is the second amendment.
**Repays:** [#37](../debt.md#37), [#42](../debt.md#42), [#47](../debt.md#47), [#53](../debt.md#53), [#54](../debt.md#54); **partly** [#44](../debt.md#44), [#46](../debt.md#46)
**Depends on:** M2-4, M2-6, M2-7, M2-8, M2-10 (all merged)

## 1. Problem

`cli/resolveAgent` returns an adapter for exactly one scheme:

```go
if parsed.GetScheme() == agentref.SchemeFake {
    return fake.New(fake.Options{}), parsed, nil
}
return nil, nil, errs.ErrCapabilityUnsupported.WithFix(
    "only `fake:` is available in this build; provider adapters land in the next milestone")
```

Everything M2-3 through M2-8 built — `openaicompat`, `anthropic`, the transport with its host and
redirect rules, the pricing table, retry and rate-limit handling — **is unreachable from the CLI.**
Every test that exercises it constructs the adapter directly in Go.

So M2-11 is not a wiring chore. It is **the first PR in which `kno baseline` can spend the user's
money**, and prime directive 4 says that path is the one we are most careful about. Framing it as
"CLI flags and docs" is how it gets reviewed as plumbing; it should be reviewed as the milestone's
second security boundary, the first having been the transport.

The corollary the first draft got wrong: **every latent defect on the real-provider path is
currently invisible, because every test in the tree runs a sub-second in-process fake.** Draft 1
scoped this PR by reading the ledger. Phase 1 found the most damaging item by reading the
executor. Both are now in scope.

| Entry | What is broken | Reachable before M2-11? |
|---|---|---|
| [#54](../debt.md#54) | The sink's recording deadline starts at **run start**, not at shutdown. Nothing sets `RecordGrace`, so it is 30s for the whole run | Only in principle — no run is slow enough |
| [#47](../debt.md#47) | Run-fatal provider failures classified per-Case: a wrong API key on a 10,000-Case run makes 10,000 requests | No |
| [#42](../debt.md#42) | The resolved-model resume gate is dead: `BaselineOptions.ResolvedModel` is caller-supplied and read before any request | No |
| [#46](../debt.md#46) | A priced-variant model is unpriced; a capped run errors every Case and reports "too many cases errored" | No |
| [#44](../debt.md#44) | Engine-chosen concurrency is recorded and emitted but no surface reads it back | Partly |
| [#37](../debt.md#37) | No OTel spans on adapter calls | No |

**The ordering consequence:** #54, #47, #42, and #46 are each a way the first real-spend run fails
badly. Shipping the wiring before them means the first PR that can spend money ships without the
stops that bound it.

## 2. Design

### 2.0 The split

**Four** PRs, not three. Pass 2 found 11a had become six packages, a proto diff, and a public-API
break in one review — the same objection §A1 uses to reject a single-PR milestone, applied inside
11a. The boundary is chosen so that **nothing that can spend money merges before the guards that
bound the spend**, and so that each diff is reviewable as one thing.

| PR | Scope | Repays | Can spend money? |
|---|---|---|---|
| **11a-0** | `executor` only: the sink-deadline fix and the `AfterRecord` hook | #54 | No |
| **11a** | Run-fatal escalation, the extracted reason seam, the resume gate, the unpriced refusal, proto | #47, #42, #53, #46 (refusal shape) | No |
| **11b** | Adapter wiring, flag surface, price override, consent, capability matrix, concurrency report | #44 (report half), #46 (rows) | **Yes** |
| **11c** | OTel spans + vhs tape | #37 | Unchanged from 11b |

**#54's own trigger says "Before M2-11", not "in M2-11"** — 11a-0 honors it literally. It is
`executor`-only, touches no proto, changes no `core` semantics, and §2.1's ordering argument
("run-fatal increases the burst at the sink") is satisfied strictly better by an earlier PR than by
a shared diff. It also carries the `AfterRecord` hook §2.4 needs, so every `executor` change in the
milestone lands in one reviewable place.

**Why the split is safe, stated explicitly because it is the strongest argument for it and draft 2
never said it:** after 11a-0 and 11a, `resolveAgent` still returns only `fake:`, and `fake` is not
an `Estimator` — so **none of 11a's escalations or refusals is reachable from the CLI.** There is no
window in which a refusal exists without its escape, and no user is worse off between any two
merges. The corollary is a real cost: 11a ships with zero CLI-reachable behavior, so its correctness
rests entirely on Go-level tests, and §6 is written knowing that.

Docs ride in the PR that changes the behavior, per CLAUDE.md — there is no trailing docs PR.

### 2.1 (11a) The sink's deadline is a shutdown bound applied from run start — #54

**This is the finding that reorders the milestone, and it is not in draft 1 at all.**

`executor.Run` builds the sink's context once, before any work starts:

```go
// executor/executor.go:236
recordCtx, recordCancel := context.WithTimeout(context.WithoutCancel(ctx), opts.recordGrace())
```

`recordGrace()` defaults to **30 seconds** (`executor.go:84-89`) and **nothing in the tree ever
sets `RecordGrace`** — `core.Baseline` passes `Concurrency`, `ID`, `Skip`, and `IsFatal` only
(`core/baseline.go:441-455`). `sinkFunc` uses that context for the durable write
(`core/baseline_record.go:891`), and `store/sqlite.go` is `ExecContext` throughout.

**Concrete failure.** `kno baseline --agent anthropic:claude-opus-5 --evals 500cases.jsonl`. At
t=30s the first `RecordOutcome` returns `context deadline exceeded`, `sinkBroken` latches
(`executor.go:255-259`), and **every subsequent result is silently discarded** — no outcome row,
absent from `CompletedCases`, and re-paid on the next `--resume`. The run ends `FAILED` with a
message about recording. Real money, spent twice, for every run over half a minute.

The comment on the line is right about the *intent* — "the grace period bounds how long a hung
sink can delay shutdown" — and the implementation applies it to the whole run instead.

**Proposal — corrected in draft 3.** Draft 2 said "once the results channel is closing, the
remaining drain is bounded by `RecordGrace`". That bounds nothing. `results` is **unbuffered**
(`executor.go:229`) and closed only after `workers.Wait()` (`executor.go:367-368`), so a send
completes when the sink receives it — by the time `close(results)` runs, the post-close window is at
most one in-flight `recordOne` call, which a per-call timeout already covers. Scoping the grace
there quietly retires the bound while every test stays green.

The window that actually needs bounding is the one the godoc already names (`executor.go:67-72`):
Ctrl-C kills `runCtx`, each of N workers finishes its current item and sends, and the sink records N
results on a context with no deadline.

So:

- `recordCtx` is `context.WithoutCancel(ctx)` with **no** deadline.
- Each `SinkFunc` call gets its own timeout (`PerRecordTimeout`, exported, default 30s), which
  bounds a hung sink without bounding the run.
- The grace is armed **when the caller's context is cancelled**:
  `stop := context.AfterFunc(ctx, func() { time.AfterFunc(opts.recordGrace(), recordCancel) })`,
  with `defer stop()` — `executor` runs `goleak.VerifyTestMain`, so an unstopped timer is a test
  failure, not a leak nobody notices.

**This is not a semantic change to `RecordGrace`; it is the first implementation that matches its
documentation.** That framing is also the answer to "is this breaking?" — `executor` is not in
CLAUDE.md's stability-promised set, and `Options` gaining `PerRecordTimeout` is additive. `Run`'s
package godoc (`executor.go:194-196`) still says "a sink that blocks forever will stall a run for
RecordGrace and then be abandoned" and is updated in the same diff.

Two consequences to state rather than discover:

- A **batched or transactional** sink is unaffected: the timeout is per `SinkFunc` *call*, and
  `core.sinkFunc` does its whole write inside one.
- `sinkBroken` still latches correctly (written and read only from the sink goroutine), **including
  on grace expiry** — so a slow Ctrl-C drain reports as a sink failure rather than a cancellation.
  Pre-existing, but this fix makes it the normal shutdown path, so it is now worth saying.

### 2.1b (11a-0) `AfterRecord`, the hook §2.4 needs

`executor` consults `IsFatal` **only when `err != nil`** (`executor.go:307`). There is no path from a
*successful* work item to shutdown, which is why §2.4's revised gate had no mechanism (pass 2, P0-2).

`executor.Options` gains:

```go
// AfterRecord runs on the sink goroutine after a result is durably recorded.
// A non-nil return ends the run without discarding the result that triggered
// it — which is what separates it from returning an error from SinkFunc.
AfterRecord func(r Result[I, T]) error
```

Additive, nil-by-default, and it keeps `Result`'s documented invariant intact — "exactly one of
Value or Err is meaningful" (`executor.go:18-21`), the invariant the alternative would have had to
amend. Returning an error from `SinkFunc` instead was rejected outright: it latches `sinkBroken`
(`executor.go:269`) and discards every subsequent result, which is #54's failure mode deliberately
reintroduced.

### 2.2 (11a) Run-fatal escalation — #47

**The constraint that shapes this.** `core` cannot import `adapters`. Prime directive 3 is
absolute, so `IsFatal` cannot write `errors.Is(err, anthropic.ErrAuthentication)`.

**Draft 1 proposed a sentinel (`errs.ErrRunFatal`) that adapters wrap. That is wrong in both
possible orientations, and the tree already documents why.**

`errs.Actionable` has a **single** `wrapped error` slot and `Wrap` replaces it
(`core/errs/errs.go:169-215`). `ErrAuthentication` already spends that slot on the provider's
sanitized cause (`anthropic/errors.go:216`).

- **`ErrRunFatal.Wrap(ErrAuthentication…)`**: `errors.As(err, **Actionable)` returns the outermost,
  so `codeOf` (`baseline_record.go:927-931`) persists `"RUN_FATAL"` instead of the adapter's code
  in `Outcome.Err`, on the event stream, and in `--json`; `ExitCodeOf` and `renderError` read the
  wrong one. **This is verbatim the [#39](../debt.md#39) defect**, which was found empirically and
  is documented at `anthropic/errors.go:79-90`.
- **`ErrAuthentication.Wrap(ErrRunFatal…)`**: `Actionable.Error()` inlines the chain
  (`errs.go:179-195`), producing a doubled `fix:` block — and there is nowhere left for the
  provider's cause, because the slot is taken.

**Revised proposal: the `retryAfterError` shape, which is the tree's own proven pattern.**

```go
// core/errs — declared where core can see it, satisfied structurally.
// core asserts: interface{ RunFatal() bool }

// adapters/agent/anthropic
type runFatalError struct{ *errs.Actionable }

func (e *runFatalError) RunFatal() bool { return true }

// Unwrap returns the embedded Actionable rather than the Actionable's own
// cause — without this the PROMOTED Unwrap jumps past it and
// errors.As(err, **errs.Actionable) answers false. See debt #39.
func (e *runFatalError) Unwrap() error { return e.Actionable }
```

Zero message change, no second `wrapped` slot, and it matches `retryAfterOf` and `billedCostOf`
— the two assertions `core` already declares. `core` gains `runFatalOf(err) bool` beside them.

**`runFatalError` cannot live in `transport`.** Draft 2's §4 put it there;
`transport.ErrRefusedDestination` and `ErrKeyBinding` are plain `fmt.Errorf` values
(`destination.go:68,72`), not `*errs.Actionable`, so there is nothing to embed. The escalation site
for those two is each adapter's `fromTransport` (`anthropic/errors.go:148-155`), which composes
correctly because `Actionable.Unwrap` reaches the inner error. A wrong package assignment is a
coordination bug, not a typo — CLAUDE.md gives each subagent only its package scope.

**And the type is extracted, not copied.** It is needed in `anthropic` and `openaicompat`, and it is
the **third** hand-written `Unwrap` override whose omission is the #39 defect (`retryAfterError`
being the first). CLAUDE.md says extract on the third occurrence. It lands in
`adapters/agent/internal/` beside the transport, with the marker methods composing — which is also
what makes §2.2b cheap.

### 2.2b (11a) The reason seam, and #53 — found by pass 2, missed by both earlier drafts

[#53](../debt.md#53) says `RETRY_REASON_TIMEOUT` is defined and never emitted, and a billed **408**
is reported as `PROVIDER_UNAVAILABLE` — a code whose schema definition is "the provider returned a
5xx". Its repayment needs *"the adapter-side reason interface — the same shape `retryAfterOf` uses
for the wait"*, trigger *"before the first tagged release"*.

That is exactly the seam §2.2 is extracting. A fourth assertion on an existing seam is cheap; a
fourth hand-rolled copy is not, which is why this is repaid here rather than deferred again. Draft 1
missed #54 by reading the ledger too narrowly and draft 2 missed #53 the same way — the pattern is
worth naming, not just fixing.

**One condition rests on prose, and it fails open.** `selfSetSpendLimit` is matched by
`strings.HasPrefix(msg, "You have reached your specified API usage limits")`
(`anthropic/errors.go:119`). The neighboring `contextTooLong` comment states the principle this
breaks: *"The match only picks the FIX line, never whether the error is terminal… so a wording
change degrades the advice rather than the classification."* Escalating on it means a provider
reword silently re-opens #47 for that one condition. Accepted rather than dropped — it fails open
(back to per-Case handling, today's behavior) rather than closed — and ledgered with a canary
trigger. The `spendLimitCode` and status-code conditions are structured and carry no such risk.

**Per-instance at the classification site, never on a sentinel.** `Actionable.Is` compares by
**`Code`** (`errs.go:205-215`), and the spend-cap 429 comes back as `ErrProvider` — a code shared
with a dozen unrelated terminal errors (`anthropic/errors.go:174-179`). Escalating on the sentinel
would make every provider error run-fatal.

**The conditions.** Draft 1 named three; the review found three more that satisfy the same
"cannot change within a run" test:

| Condition | Where | Why it cannot change within a run |
|---|---|---|
| Rejected credential (401/403) | `anthropic.ErrAuthentication`, `openaicompat.errorFor` | The key is read once at construction |
| Spend-cap 429 (`enforced_spend_limit_reached`) | `anthropic/errors.go:111` | The provider's own cap; waiting cannot clear it |
| Refused destination / key-binding mismatch | `transport.ErrRefusedDestination`, `ErrKeyBinding` | Fixed by config, read once |
| **400 `selfSetSpendLimit`** | `anthropic/errors.go:238-241` | The code's own fix line says *"retrying will not clear it"* |
| **402 Payment Required** | `anthropic/errors.go:220-223` | An unpaid account does not become paid mid-run |
| **404 model-not-found** | `anthropic/errors.go:225-229` | A typo'd model name errors all 10,000 Cases |

**Deliberately NOT escalated:** a plain 429, a 5xx, a truncation, a refusal. Escalating any
converts a recoverable run into a dead one — strictly worse than the per-Case handling they have.
(Phase 1 confirmed this list is right; no change.)

**Proto change, and draft 1 said there was none.** `sinkFunc` uses `draining` as the discriminator
for the orphan reason:

```go
// core/baseline_record.go:851-855
reason := ORPHAN_REASON_CANCELLED
if draining.Load() { reason = ORPHAN_REASON_BUDGET_EXCEEDED }
```

A run aborted by a rejected credential would report, for every in-flight charged Case, *"The cost
or call cap could not admit another attempt."* [#52](../debt.md#52)'s repayment text exists
precisely because *"a run stopped by a human is not a run that ran out of money"*; run-fatal is a
third case. **`OrphanReason` gains `ORPHAN_REASON_RUN_FATAL`** — additive, `buf breaking` clean —
and the discriminator becomes a three-valued reason rather than a bool.

**Exit code: `ExitError`, which is `1`.** (Draft 1 wrote "(2)"; `2` is `ExitBudgetStopped`,
`errs.go:19-26`. The reasoning was right, the number was wrong, and exit codes are a post-1.0
covenant.) No new code: the CLI grammar's codes are about what the user does next, and "fix your
config and re-run" is the same next step as every other `ExitError`.

### 2.3 (11a) The unpriced refusal becomes run-fatal — #46 (refusal shape only)

**Draft 1's design was unimplementable and its escape hatch was a dead end the tree had already
removed once.** Both findings are upheld:

- `checkFeasible` has no Case and never calls `Estimate`. Its only price signal is
  `planningCostPerCall()`, and when a cost cap is set `validate` has already guaranteed
  `EstCostPerCallUSDMicros > 0` (`core/baseline.go:496`) — so the signal draft 1 needed **cannot
  appear at the place draft 1 put the check.**
- `--cost-per-call-usd` does **not** override an `Estimator` (`core/baseline_budget.go:45-49`), and
  `unpriceable`'s own godoc records that advertising it *"would send the user down a dead end —
  which the first version of this message did"* (`baseline_budget.go:96-99`). Draft 1 reintroduced
  it verbatim, in the fix line and in the edge-case table.

**Revised proposal: keep the refusal where the adapter already knows the answer, and make it
run-fatal.** `errUnpriceable` already exists as a sentinel, already distinguishes "refused before
any call" from "failed after a paid call" (`baseline_budget.go:90-95`), and is already returned
before `Authorize`. Wrapping it run-fatal means the **first** Case refuses and the run ends once,
with a message about pricing — instead of 10,000 Cases erroring into a verdict that names nothing
about pricing.

No new Ring-0 method, so no public-Go-API change. This is strictly cheaper than draft 1 and it
reuses the machinery §2.2 is building anyway.

**The real escape is a per-token override, not a per-call scalar.** `pricing.EstimateWithPrice`
exists for exactly this and says so: *"It exists for the price-override flags the plan schedules
for the CLI wiring PR"* (`pricing/estimate.go:112-114`). 11b adds `--price-input-per-mtok` /
`--price-output-per-mtok`, routed through it. They are a **pair**: `EstimateWithPrice` returns
`ErrUnpriced` unless both are set and `maxOutputTokens` is positive (`estimate.go:113-122`). An
override **fills a missing row only** — it does not silently replace a row that exists and
disagrees, which is Q4's hazard closed rather than asked.

**11a's fix line must not name them.** The flags land in 11b, so between the two merges a fix line
naming them points at nothing — the exact defect §2.9 rejects `kno agents` for. 11a's refusal names
only `--max-cost-usd` (drop the cap), and 11b amends it to add the override. A fix line is a
promise; a promise dated for the next PR is not one.

**#46 is only PARTLY repaid, and draft 1 was wrong to claim it whole.** The entry's deferred item
is *"variants have no rows"*, trigger *"before the first tagged release"*. This PR changes the
shape of the refusal and adds an override; it adds no rows. The rows are still owed, from a human
reading the provider's published rates. Claiming otherwise would be the same false repayment
[#42](../debt.md#42)'s own text records and corrects.

### 2.4 (11a) The resolved-model gate moves to first-response time — #42

Today `checkResumable` compares `run.case_execution.resolved_models` against
`BaselineOptions.ResolvedModel`. The option is caller-supplied and read at `openRun` **before any
request**, so the only value it could ever hold is one a previous run recorded — the check
comparing a value to itself.

**Proposal.** Delete `BaselineOptions.ResolvedModel`. Move the check to the first response that
reports a model. Three corrections from review:

**(a) State placement.** Not a field on `BaselineOptions`: every method on it has a **value
receiver**, so `opts` is copied per call and a `sync.Once` field is a `go vet` copylocks failure
with `govet` in the lint bundle. The state is a `sync.Once` plus the recorded set declared in
`Baseline` and captured by the closure — the same shape as `var draining atomic.Bool`
(`core/baseline.go:437`).

**(b) The gate must not discard the answer, and draft 2 named no mechanism for that.** Draft 1 had
the gate return an error from the response path, which routes a **paid, scoreable** Case through
`workFunc`'s error path and records it as an agent error — the identical mistake
`SettlementOvershoot` already fixed once (`baseline_invoke.go:156-159`). Draft 2 said "score the
Case, then abort separately" and pass 2 correctly found that nothing in the tree can express it:
`IsFatal` is consulted **only when `err != nil`** (`executor.go:307`), `sinkFunc` branches on
`r.Done()` which is `r.Err == nil` (`baseline_record.go:862`), `workFunc` cannot cancel `runCtx`,
and returning an error from the sink latches `sinkBroken` and discards every later result — #54's
failure mode, reintroduced.

**The mechanism is `AfterRecord`** (§2.1b), which 11a-0 adds: the Case is scored, recorded, and
durable; then `AfterRecord` sees the recorded result, the gate fires, and the run ends. The answer
we paid for is kept, `Result`'s "exactly one of Value or Err" invariant is untouched, and
`Stats.Failed` does not count a Case the store recorded as scored. This is why the gate is in 11a
and its hook is in 11a-0 rather than both being invented at implementation time.

**(c) `checkResumable` is called twice** (`baseline.go:341` probe, `baseline_run.go:33`). The
resolved-model arm is removed from both. `resolvedModelChanged`, `recordedModels`, and
`staleFix`'s `modelChanged` parameter move to the new gate rather than being deleted — the set-
membership logic and the "pin the model" fix line are both still correct, only relocated.

**Honest accounting of what the abort does not fix.** Review is right that draft 1 understated it.
`IsFatal` is consulted *after* the result is on the channel, and `cancel()` reaches other workers
asynchronously (`executor.go:305-315`), so up to `concurrency-1` further Cases can be recorded
under the new model. The run is left as a baseline whose `AggregateScore` blends two models.
`incomplete_reason` says so in prose and the fix line says re-run without `--resume`.

**A machine-readable "unusable as a reference" marker is deliberately NOT added here.** There is no
consumer: the first stage that reads a Baseline as a reference is Valuation, which does not exist.
Adding the field now is dead code that lands ahead of its reader — the exact trap #42 records and
this plan is repaying. New ledger entry, triggered to the first consuming stage.

### 2.5 (11b) Consent — refuse, rather than prompt with a number nobody has

**Prime directive 4 is violated on today's `main` the moment a real adapter is reachable.** Verified,
and pass 2 re-verified it:

1. Unpriced model, no cost cap, no scalar → `estimate()` takes the `err != nil && !capped` arm and
   returns the scalar, which is `0` (`baseline_budget.go:62-66`).
2. `planningCostPerCall()` → `WorstCase()` is `{}` → falls back to the scalar → `0`.
3. `confirmRun` returns `nil` **before ever calling `PreConfirm`**
   (`baseline_budget.go:129-131`).

`kno baseline --agent anthropic:claude-opus-5-fast --evals 10k.jsonl` makes **10,000 real calls with
no prompt, no printed figure, and no `--yes`.** The asymmetry is backwards: a *priced* model with no
cap does prompt.

**Draft 2's fix does not work, and pass 2 is right.** Removing the early return reaches `PreConfirm`
with `CostUSDMicros: 0`, and `budget.go:611-625` latches:

```go
if confirm == nil || threshold <= 0 || total.CostUSDMicros < threshold {
    g.confirmed = true   // latches, and DISARMS the per-operation prompt
    return true, nil
}
```

`0 < threshold` for every positive threshold, so the run proceeds silently — byte-identical to
today. `confirm` and `threshold` are unexported with no accessor (`budget.go:99-100`), and
`budget.Estimate` has no way to say "unknown". Draft 2 specified behavior the code cannot produce,
and it did so while never listing `stats/budget` in §4 — a package with an 85% floor, a 95.4
ratchet, property tests, and prime-directive-4 ownership.

**Revised proposal: refuse, with an explicit opt-in.** An unpriced model is refused unless
`--accept-unknown-cost` is passed.

- `core`-only. No `stats/budget` change, no `ConfirmFunc` signature change (which would break all
  three CLI closures and any API caller).
- It is **greppable** — in a CI config, in shell history, in a code review. A dialog reading
  "10,000 Cases, per-Case cost unknown" gives a human no basis to decide and is a thing people click
  through. A flag someone had to type is consent; a prompt that cannot state a figure is theater.
- It composes with §2.3: the same run-fatal refusal, with one more escape.

**The two states are distinguishable, with one caveat.** `fake:` is not an `Estimator`; an unpriced
provider model is an `Estimator` that returned `ErrUnpriced`. Draft 2 wrote this as a general rule
and it is not one: `exec:` and `tuned:` (`agentref.go:40-44`) are also non-`Estimator`s whose cost
is emphatically not zero. Neither is wired in 11b, so it is latent — the rule is written as
"not an `Estimator` ⇒ this Agent cannot price itself; the scalar governs", not "⇒ free".

**And `--yes` must print what it is consenting to.** `confirmFunc` today always declines
interactively (`cli/render.go:104-116`, *"the huh prompt lands with the TUI"*), so 11b's only usable
real-provider invocation is `--yes` — which returns true immediately and prints nothing. Shipping a
money path whose entire consent surface is a silent blanket flag is not defensible. 11b prints the
estimate under `--yes`, unconditionally, before the first call. That is `cli`-side and needs no
`stats/budget` change either.

| `--price-output-per-mtok` | Paired with the above — `EstimateWithPrice` needs both (`estimate.go:113-122`) |

**`--allow-non-default-host` is removed.** Draft 1 claimed *"the transport refuses otherwise"*.
No such refusal exists: `Policy` has `AllowInsecureHTTP` and `AllowPrivateAddress` only
(`destination.go:52-63`). What is scoped to the default host is the *default key*
(`keybinding.go:127-140`). The flag was a no-op or an invented refusal.

**`--cost-per-call-usd` keeps its current meaning and gains an honest help string**: it applies
only when the Agent is not an `Estimator` (`exec:`, `fake:`). For a provider model the override is
per-token. Draft 1 had this backwards.

**`validate` must change.** It refuses **any** cost cap without `--cost-per-call-usd`
(`baseline.go:496`), so the flagship invocation `--agent anthropic:claude-opus-5 --max-cost-usd 5`
is refused today even though the adapter prices every Case perfectly — and the scalar the user is
forced to supply is then ignored. Revised: the requirement applies only when the Agent is not an
`Estimator`.

**The `KNO_*` column is deferred, not built.** `grep` for `os.Getenv`/`LookupEnv` outside tests
returns exactly two hits, both in `transport/keybinding.go:131,134` for API keys: **there is no env
mechanism in the CLI at all**, no `kno.yaml` loader, and no precedence machinery. `DESIGN.md:294`
specifies **three** layers — every field mirrored by a flag and a `KNO_*` var in a `kno.yaml` — and
draft 2 listed a mirror column for thirteen flags while §4's `cli` row said "flags, `kno doctor`,
consent, concurrency report". That is specifying a config system in a table cell.

Per CLAUDE.md's opening rule, DESIGN.md and this plan disagreeing is a stop-and-flag rather than a
silent pick. Flagged: **11b ships flags only.** The env and `kno.yaml` layers land with the config
work, ledgered — `kno.yaml`'s schema is a post-1.0 covenant and the shape is load-bearing, which is
a reason to design it deliberately rather than as a column here. Two shipped fix lines already
promise `kno.yaml` (`errs.go:48`, `errs.go:141`) and point at nothing; that is the same defect
§2.9 fixes for `kno doctor`, and it is now on the ledger rather than in a fix I am pretending to
make.

**Precedence, once the layers exist:** flag beats env beats file beats default. Stated here so the
config PR inherits a decision rather than re-litigating one.

### 2.7 (11b) `--base-url` composes into the ref — and what is actually still open

`openaicompat.Options.Ref`'s godoc names the hazard: a parsed ref rather than a model string plus a
URL string, because *"agentref is where the credential-in-a-URL and control-character refusals live,
and a second entry point that skipped them would be a second place for a key to reach the Run
record"* (`config.go:69-73`). So `--base-url` composes into the `AgentRef` and is parsed by
`agentref.Parse`. One validator, one entry point. That much of draft 2 stands.

**Draft 2's security claim did not.** It said a query-string credential *"is refused by nothing"*.
It is refused today, by the validator every composition goes through
(`agentref.go:234-238`), which rejects **both** query and fragment, non-echoing, with the rationale
in the comment and the case found by the fuzzer. Draft 2 billed §2.7 as a security boundary and
built a refusal, an edge-case row, and a test on top of a premise that was false. Cited here, not
re-tested.

**What is genuinely open is the path-embedded credential**, which draft 2 mentioned in one trailing
clause and never designed for. `https://gw.example/v1/sk-abc123` parses clean, canonicalizes clean,
is stored in `Run.agent.base_url`, emitted on `RunStarted` (`baseline_run.go:44`,
`baseline_record.go:445`), rendered in `--json`, and survives `kno purge` — the four-copy failure
`agentref.go:133-139` records for the target slot and did not extend to the path.

**And it is genuinely hard**, which is why the decision is to accept and document rather than to
ship a heuristic. A path segment is indistinguishable from a legitimate route prefix: `/v1`,
`/openai/v1`, `/api/v3/deployments/gpt-4o` are all real. Refusing segments matching known key
prefixes (`sk-`, `sk-ant-`, `ghp_`, `AIza`) is a blocklist that fails **open** on every provider not
in the list while false-positiving a route that happens to start with one. **Accepted, documented in
`SECURITY.md` under the credential-in-URL forms, and ledgered** — with the honest note that the
mitigation is "do not put keys in paths; use `--key-env`", not a refusal.

**Two composition holes pass 2 found, both fixed at the CLI edge:**

- **`--agent openai:m@https://a/v1` *and* `--base-url https://b/v1`.** `splitBaseURL`
  (`agentref.go:184-199`) takes the first `@` whose remainder is absolute, so the base URL becomes
  `https://a/v1@https://b/v1` — host `a`, path `/v1@https:/b/v1`, no error. The run goes to `a` with
  a garbage path and `--base-url` is silently ignored. **Refused when both are present**, rather
  than picking a winner: two ways of saying the same thing, disagreeing, is user error.
- **A `--base-url` that is not absolute http(s).** `--base-url h/v1` composes to `openai:m@h/v1`;
  `splitBaseURL` finds no absolute URL and the flag is silently absorbed into the **model name**,
  giving a 404 that says "check the model name". A one-slash typo (`https:/h`) is worse: it is
  refused with *"puts a URL where the model belongs. A base URL is introduced by `@`"* — a message
  about `@` for a user who never typed one. **The CLI validates `--base-url` as absolute http(s)
  before composing**, and maps `ErrMalformed` from the base-URL half back onto the flag name.
  `anthropic.go:285`'s existing *"write `--base-url` as a full URL"* is the right wording and is
  reused at the edge.

Pass 2 checked the other composition cases and they are safe: a model containing one `@`
(`my-model@v2`) splits correctly; userinfo in the base URL is caught and redacted by `redactRef`;
`fake:` + `--base-url` is refused by `schemeUsesBaseURL`; an `@` inside the base URL's path or query
is handled by the first-absolute-URL rule.

### 2.8 (11b) The concurrency report — #44

`Run.concurrency` is recorded and `ConcurrencyReduced` is emitted; no surface reads either back.

Draft 1 put the line only in the post-run report. **#44's own text names the prompt**: *"the consent
prompt quotes a run whose width has already been cut and does not say so; the prompt is the natural
place for the report."* Draft 2 moved it there. **Draft 3 moves it back, because the prompt cannot
carry it.**

`budget.ConfirmFunc` is `func(ctx, Estimate, Remaining) (bool, error)` (`budget.go:88`) — there is
no channel for a `ConcurrencyDecision`. The data exists in the right place at the right time
(`checkFeasible` at `baseline.go:347` really does run before `confirmRun` at `:350`), but it exists
inside `core`, which cannot print (CLAUDE.md forbids `fmt.Println` outside `tui/`) and cannot reach
the ConfirmFunc without changing its signature — breaking all three CLI closures and any API caller,
in a package draft 2 never listed in §4.

So the reduction lands in the human report and in `--json` now, and **#44 stays partly open** for
the prompt half, triggered to the TUI milestone that owns the prompt. Claiming it whole would be the
false repayment #42's own text records.

`--json` gains **hand-written** fields, not the embedded `*knov1.ConcurrencyDecision`.
`cli/jsonreport.go`'s header is a scoped ADR-0001 exemption: the struct is hand-written *"so it
should not shift underneath them when the schema gains a field"*, and embedding the proto message
would emit `int64` fields as bare numbers — the exact divergence from the generated OpenAPI spec
ADR-0001 bans.

### 2.9 (11b) The capability matrix, and the command that is already named

**Draft 1's premise was false: `Capabilities()` is never called anywhere in `core`, `cli`, or
`executor`** — grep across non-test files finds only the three adapter implementations and the
interface declaration. `core/ring0.go:31-33`'s godoc is aspirational. The refusal that actually
exists is at **adapter construction** (`openaicompat/config.go:95-101`,
`anthropic/anthropic.go:130-135`), which is still before any spend, so the user-visible behavior is
fine — but the plan must not claim a mechanism that is not there.

**The command is `kno doctor`, not `kno agents`.** `errs.ErrCapabilityUnsupported.Fix` already
says *"run `kno doctor` to print the capability matrix"* (`errs.go:66`) and no such command exists.
Shipping `kno agents` would leave a shipped fix line pointing at nothing. Read-only, no spend,
rendered from `Capabilities()` at runtime and snapshot-tested — generated rather than handwritten,
because a handwritten matrix drifts silently and the whole point is that it is true.

(Phase 1 confirmed "agents" is *not* vocabulary drift — `Agent`/`--agent`/`AgentRef` are
established. The collision with the shipped `doctor` fix line is the real problem.)

### 2.10 (11c) OTel — #37

`--otel-endpoint`, off by default (no env mirror — see §2.6; the env layer lands with the config work). A span per stage, per adapter
call, per plugin invocation, correlated by run ID. **Spans carry IDs and metrics only** — never
Case input, never Response content, never the system prompt — asserted by an exporter that fails
on any attribute value containing a substring of the fixture's content.

**`otlptracehttp`, not `otlptracegrpc`.** `go.mod` has three direct dependencies today
(`go-cmp`, `goleak`, `protobuf`). The gRPC exporter pulls `grpc`, `grpc-gateway/v2`, `go-logr`,
`cenkalti/backoff`, and the SDK tree — roughly 15 modules, each needing the dependency-
justification paragraph CLAUDE.md requires. The HTTP exporter avoids grpc entirely and is the
cheaper design draft 1's Q4 did not consider; a build tag is a worse answer than not taking the
tree.

**`charmbracelet/log` is not in `go.mod` either**, and CLAUDE.md mandates it for structured
logging. §5's "logged at WARN once" has nothing to log through. 11c adds it, or 11c's warning is
routed through whatever the tree settles on — flagged rather than assumed.

`DESIGN.md:399` places OTel export at v0.3 while `CLAUDE.md` says tracing is built in. This PR
resolves it in CLAUDE.md's favor and edits `DESIGN.md`: the flag being off by default makes the two
compatible — instrumentation built in, export opt-in.

## 3. Alternatives considered

**A1 — One PR for all of M2-11.** Rejected. It merges the spend path and its guards, so the review
that would catch a missing guard is the same review checking a flag surface, a capability matrix,
an OTel dependency tree, and six ledger repayments.

**A2 — Wiring first, guards after.** Rejected, and Phase 1 verified the danger rather than taking
it on faith: with `--max-calls 1000` and a wrong key on `main`+11b-without-11a,
`invokeWithRetry` returns a non-retryable `ErrAuthentication` per Case, `invokeOnce` settles
`Spend{Calls: 1}` on the error path (`baseline_invoke.go:318-322`), and `IsFatal` matches only
`ErrBudgetExceeded` — so all 1000 calls are made and settled.

**A3 — A sentinel (`errs.ErrRunFatal`) instead of the interface assertion.** **Rejected in draft 2;
it was draft 1's proposal.** Both wrapping orientations are broken (§2.2), and a third defect
applies to both: `FromProto` rebuilds an `Actionable` with `Unwrap() == nil` and only the outermost
`Code` (`errs.go:249-265`), so a run-fatal error crossing the wire — a Ring-2 plugin agent, the api
SSE path — **silently loses its run-fatality**, and #47's sweep returns for plugin adapters. The
interface assertion has the same wire limitation, which is why §7 Q1 asks about the plugin boundary
explicitly.

**A4 — Keep the resume gate at `openRun`, CLI passes the recorded model back.** Rejected as
circular; confirmed by review.

**A5 — Refuse an unpriced model unconditionally.** Rejected: it makes table completeness a hard
dependency for every run, so a model shipped between two Kno releases is unusable rather than
merely unbounded. Confirmed by review.

**A6 — Draft 1's `checkFeasible` unpriced refusal.** Rejected as unimplementable (§2.3): the
signal cannot appear there.

**A7 — Add a Ring-0 `WorstCase() (budget.Estimate, error)` probe** so `core` can detect unpriced
up front. Rejected: `core.Estimator` is part of the stability-promised public Go API, and §2.3's
run-fatal refusal gets the same user-visible outcome — one refusal, before the second call — at
zero API cost.

**A8 — Set `RecordGrace` to a large value instead of restructuring (§2.1).** Rejected. It moves the
cliff rather than removing it: any run longer than the new value has the same silent-discard
failure, and the value would have to be guessed against eval-set size. The bug is that a shutdown
bound is applied to a run.

## 5. Edge cases

| Case | Mitigation |
|---|---|
| Run longer than 30s (§2.1) | Per-call timeout; the grace arms on caller cancel. Test: a sink slower than the old grace, run longer than it, assert every outcome is durable |
| Sink genuinely hung on one call | `PerRecordTimeout` fires; `sinkBroken` latches as today |
| Ctrl-C with N workers mid-item | Grace arms on cancel and bounds the drain — the bound the godoc has always promised and no implementation has kept |
| Slow Ctrl-C drain hits the grace | Reports as a **sink failure**, not a cancellation. Pre-existing, but now the normal shutdown path |
| Run-fatal fires with N-1 Cases in flight | `draining` set; in-flight Cases settle; orphan reason is `RUN_FATAL`, not `BUDGET_EXCEEDED` |
| Run-fatal fires on an already-charged Case | Settles through `sinkFunc`'s retry-exhausted branch (M2-10d). Test asserts guard and store agree |
| Resolved-model gate fires | The Case is **scored**, not discarded. Up to `concurrency-1` further Cases are recorded under the new model — stated, not hidden. `incomplete_reason` names both models |
| Gate races: N workers respond simultaneously | `sync.Once` declared in `Baseline`, captured by the closure — never a field on `BaselineOptions` (copylocks) |
| Resume where the recorded set is empty | Nothing to compare; inert. Covered by `TestAnUnknownResolvedModelDoesNotBlockAResume` |
| Unpriced model + cost cap | Run-fatal refusal on the **first** Case. Fix line names the per-token override, **never** `--cost-per-call-usd` |
| Unpriced model, **no** cap, no override | **Refused** unless `--accept-unknown-cost` (§2.5). A prompt that cannot state a figure is not consent |
| Unpriced model, **call** cap only | Same refusal. The call cap bounds calls, not dollars |
| `exec:` or `tuned:` agent | Not an `Estimator`, and **not free** — the scalar governs. The discriminator is "cannot price itself", never "costs nothing" |
| `--base-url` with a credential in userinfo | Already refused (`destination.go:96-102`, `agentref.go:240-243`), non-echoing. Not re-tested |
| `--base-url` with a credential in the **query string** or fragment | **Already refused** (`agentref.go:234-238`), non-echoing, fuzzer-found. Cited, not re-tested |
| `--base-url` with a credential in the **path** | **Accepted and documented**, not refused — a path segment is indistinguishable from a route prefix, and a key-prefix blocklist fails open. `SECURITY.md` + ledger |
| `--base-url` given alongside an `@` form in `--agent` | Refused. `splitBaseURL` would otherwise build `https://a/v1@https://b/v1` and silently ignore the flag |
| `--base-url` not absolute http(s) | Refused at the CLI edge, naming the flag — otherwise it is absorbed into the model name and returns a 404 about the model |
| `--key-env` naming an unset var, `anthropic`, default host | Refused at construction. No spend |
| `--key-env` naming an unset var, `openaicompat` | **Not refused today**: `connect` omits the `Authorization` header (`config.go:229-234`) and the provider 401s per Case. Now run-fatal, so it aborts once — but 11b should refuse it at construction. Ledgered if not fixed |
| `--key-env` naming an unset var, `anthropic`, **non**-default host | Deliberately permitted (`anthropic.go:333-338`): a non-Anthropic host may legitimately need no credential |
| `--temperature` unsupported by the model | Refused at **adapter construction**, not by a ring-0 check (§2.9) |
| OTel endpoint unreachable | Never fails the run. One WARN, not per span |

## 6. Test plan

**11a**
**11a-0**
- **#54, uncancelled path**: a sink slower than the grace, on a run longer than it, asserts every
  outcome is durably recorded and a resume re-pays nothing. Timings from the ledger's own repro —
  250ms grace, six 100ms items — not "a run longer than 30s", which does not belong in `make test`.
  Mutation: restore the run-scoped deadline; must fail with discarded outcomes.
- **#54, shutdown path** — the half draft 2's test plan omitted entirely, and without which the
  Ctrl-C bound could vanish with the suite green. Cancel the caller mid-run against a sink that
  ignores its context; assert `Run` returns within roughly `RecordGrace`. Mutation: drop the
  `context.AfterFunc` arming; must hang past the bound.
- `AfterRecord` returning an error ends the run **and** the triggering result stays durable.
  Mutation: route it through `SinkFunc`'s error return instead; the recorded-outcome assertion must
  fail (that is #54's failure mode, and the test exists to pin the difference).
- `goleak` catches an unstopped grace timer — `defer stop()` is load-bearing, not decoration.
- Each of the **six** run-fatal conditions ends the run early. **Assertion corrected for
  concurrency**: `IsFatal` fires after the result is on the channel and `cancel()` propagates
  asynchronously (`executor.go:305-315`), so at `DefaultConcurrency()` between 1 and 8 Cases will
  have been recorded. Two tests: `Concurrency: 1` asserts exactly `attempted == 1`; the concurrent
  case asserts `attempted <= concurrency+1 && attempted < 50`. Draft 1's flat `attempted == 1` on a

  Go picks uniformly at random (`executor.go:350-362`), so one more Case can dispatch after cancel.
  `Concurrency: 1` is genuinely deterministic and keeps the exact `attempted == 1` assertion.

- Draft 1's *"`BaselineOptions.ResolvedModel` is gone — a compile-time assertion via its absence"*

## 8. Rollback

Each PR is independently revertable, and **each owns both sides of every seam it introduces** — the
rule draft 2 stated in §8 while violating it in §4.

- **11a-0** adds `executor` surface. Reverting it breaks 11a's gate, so 11a is reverted with it or
  not at all; stated here rather than discovered.
- **11a** is unreachable from the CLI (§2.0), so reverting it changes no user-visible behavior.
  Its proto addition is additive — old readers are unaffected.
- **11b** reverts the CLI to `fake:`-only, which is `main` today. No data migration, no schema
  change, no stored run becomes unreadable.
- **11c** is a flag defaulting off.

**One-way doors, plural** — draft 2 named only the first:

1. **11b's flag names**, which become the CLI covenant at 1.0. They now match names already in
   shipped error text (`--key-env`) rather than invented ones.
2. **11a's removal of `BaselineOptions.ResolvedModel`**, a public-Go-API break. Pre-1.0 with a
   CHANGELOG migration note.
3. **`ORPHAN_REASON_RUN_FATAL`'s enum value**, which is a wire covenant the moment it ships.
